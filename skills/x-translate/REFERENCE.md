# Reference — x-translate

Detailed companion to [SKILL.md](SKILL.md). Read when you need the full style guide,
X-access fallbacks, or design tokens.

## Fetching X content — fallback ladder

X aggressively blocks automation. Try in order:

1. **`read` tool** on the `x.com/.../status/<id>` URL — usually returns `twitter-blocked`.
2. **Browser tool** — `open` the URL, wait ~3–4s, `observe()`, then `tab.extract('text')` or
   `tab.evaluate(() => document.body.innerText)`. The tweet card usually shows the post text and,
   if it's an Article, a card link.
3. **Article behind login wall** — X Articles often redirect to `/i/jf/onboarding/web` (login).
   Do **not** attempt login. Note the **article id** in the redirect URL
   (`redirect_after_login=%2Fi%2Farticle%2F<ID>`), then:
   - `web_search` for the title text in quotes + a likely mirror domain:
     `"<exact title snippet>" site:huggingface.co`, or `"<title>" medium`, or bare `"<title>"`.
   - `read` the cleanest full-text mirror (HuggingFace community blogs and Medium reprints are
     common and well-formatted).
4. **Thread / multi-tweet posts** — read each tweet text via browser `observe`; the post body is
   in the tweet `article` element. Concatenate in order.

Always record the **original post URL** (`https://x.com/<handle>/status/<id>`) — it goes in the
source banner regardless of which mirror supplied the text.

## Vietnamese translation style guide

- **Faithful over literal.** Preserve the author's meaning and tone. Rephrase for natural
  Vietnamese rather than word-for-word.
- **Voice.** Most X essays are casual-literate. Keep that register — not stiff, not slangy.
- **Proper names:** keep in original form (Richard Hamming, Claude Shannon, Karpathy, Andrew Ng).
- **Technical terms** widely used untranslated — keep English, italicize on first use, gloss once:
  - *backprop*, *mixture of experts*, *baseline*, *ablate/ablation*, *overfit*, *config*,
    *harness*, *eval*, *transcript*, *benchmark*, *compute* (tài nguyên tính toán).
  - Vietnamese-render once where it aids the reader, e.g. "đánh giá (eval)".
- **Quote attribution:** keep `"The Bitter Lesson"` style — English title in italics + Vietnamese
  gloss in parentheses.
- **Emphasis** maps: source `*italics*` → Vietnamese `<em>`; don't add emphasis that isn't there.
- **Pull quotes:** pick 1–2 of the sharpest sentences for `figure.pullquote` per long essay.
- **Diacritics & spelling:** correct Vietnamese with full diacritics. Proofread numbers, names,
  years (1991, 1997, 1986, etc.) against the source.
- **Measure words / idiom:** localize idioms to natural Vietnamese equivalents, don't translate
  literally (e.g. "where the bodies are buried" → "nơi giấu những điều giấu giếm").

## The artifact template (`templates/article.html`)

A self-contained magazine-style reader. Fill two things:

### Config JSON (top of file)
```html
<script id="xlate-config" type="application/json">
{
  "title": "Làm sao để giỏi nghiên cứu",
  "titleAccent": "giỏi nghiên cứu",
  "lead": "Thực ra chẳng ai dạy bạn nghiên cứu cả…",
  "author": "vivek",
  "sourceUrl": "https://x.com/itsreallyvivek/status/...",
  "sourceLabel": "vivek — “how to be good at research” (X / Twitter)"
}
</script>
```
- `titleAccent` = the substring of `title` to render in the accent color (italic). Optional.
- The topbar brand shows `thư viện đọc` by default; change only if deploying to a non-`read` project.

### Body (`<article id="xlate-body">`)
Use these elements:
- `<p>` — paragraphs.
- `<h2>Tiêu đề phần</h2>` — section headings. **Auto-numbered and auto-added to the TOC.**
  Optionally write the id yourself (`<h2 id="...">`); otherwise it's slugified from the text.
- `<blockquote>` — indented italic quote with accent left-border.
- `<figure class="pullquote">…</figure>` — large centered accent pull quote (use sparingly).
- `<hr class="ornament">` — ornamental section break (◆ ◆ ◆).
- `<strong>`, `<em>` — emphasis.

Everything else (progress bar, theme toggle, TOC spy/active state, source banner, footer note) is
generated by the built-in JS from the config + your `<h2>`s. You do not write them by hand.

### Design tokens (CSS `:root` variables)
Light: warm paper `--bg #f6f2ea`, ink `#211d18`, accent terracotta `--accent #b4502a`.
Dark variant under `:root[data-theme="dark"]`. Fonts: Newsreader (serif body) + Inter (sans UI) +
JetBrains Mono (section numbers), all via Google Fonts (Vietnamese subset supported). Change
`--accent` to recolor the whole artifact.

## Read-aloud (Native / Web Speech only)

The template has a built-in floating **"Đọc bài"** player. It is **Native-only**: it uses the
device's own Web Speech API (`speechSynthesis`) with a `vi-VN` voice when one is installed.
Free, nothing to generate, **zero added file weight** — the read button just speaks the page.

**Deliberate decision: no AI/inline audio.** Pre-generated edge-tts neural audio was tried and
removed — inlining a long essay's MP3 as base64 bloats the HTML to ~5 MB, which is not worth it
for a reading artifact. Keep artifacts light (tens of KB). Do not re-introduce an `audio` field,
base64 data-URIs, or a sibling `.mp3` (and `scripts/prepare-static.mjs` only serves `.html`/`.md`
anyway, so a sibling asset would 404).

### How it works
- `analyze(#xlate-body)` builds the whitespace-normalized `textContent` plus a char→text-node map.
- `setRanges()` splits that text into sentences; `wrapRanges()` wraps each sentence's char range
  in `<span class="xr-sent" data-i>` (grouped per parent, so a sentence crossing `<em>`/block
  boundaries still highlights as one unit).
- Playback speaks sentence-by-sentence (`SpeechSynthesisUtterance`); `onend` chains to the next,
  `setActive(i)` highlights + scrolls the current sentence. Speed select restarts the current
  sentence at the new rate (Web Speech can't change rate mid-utterance). The progress bar /
  "câu X / Y" track the sentence index. If `speechSynthesis` is absent, the button hides itself.

### Alignment invariant
- **Section numbers stay CSS counters** (`#xlate-body h2::before { content: counter(sec) }`).
  Never add a `<span class="sec-num">` with the number as text — it would enter `textContent` and
  shift every sentence range after it, misaligning the highlight.

## Document delivery gate (mandatory)

The delivered artifact is a **shared/external** deliverable. Before shipping, verify:
- A prominent link to the **original post** is present (built-in source banner + footer note).
- The **original author is credited** (name + handle in source label / meta).
- **No AI/agent authorship markers**: no "Generated with Claude Code", no Co-Authored-By, no
  "as an AI" phrasing. The artifact reads as a human-made Vietnamese translation.
- No internal ticket IDs, no local file paths, no session-internal labels leak into the HTML.

## Delivering

```bash
cd ~/Local/Work/solashi/share-artifacts
./deliver.sh /tmp/<slug>.html read        # viewer: https://artifacts.hoangtrung.dev/read/<slug>
```
- Prerequisite: `wrangler` authenticated (`npx wrangler login` or `CLOUDFLARE_API_TOKEN`).
- Default project `read`. Pass a different project only when clearly appropriate; ask if unsure.
- Return both URLs `deliver.sh` prints (viewer + raw).
- Self-contained only: the template already is. Don't introduce external `<link>`/`<script>` to
  local files (Google Fonts CDN is fine — it resolves on the deployed site).
