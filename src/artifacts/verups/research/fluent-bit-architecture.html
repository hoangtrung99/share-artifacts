Fluent Bit Architecture

verup (bse-cb) — eks cluster "point" — ap-northeast-1

1 — Tổng quan

Fluent Bit là một log processor/forwarder siêu nhẹ (viết bằng C), được deploy dưới dạng DaemonSet trên mỗi EKS node. Nhiệm vụ: thu thập tất cả log từ container, hệ thống, và OS-level — làm giàu metadata — rồi đẩy lên CloudWatch Logs.

Trong dự án này, Fluent Bit chạy song song với CloudWatch Agent trên cùng namespace amazon-cloudwatch, nhưng hoàn toàn khác nhiệm vụ. Image: aws-for-fluent-bit:stable

Tiêu chíChi tiết

Tại sao cần cả hai? — Logs và Metrics là hai khía cạnh hoàn toàn khác nhau của observability. Fluent Bit xử lý log text (stack traces, error messages, request logs). CloudWatch Agent thu metrics dạng số (CPU %, memory bytes, network I/O). Cả hai kết hợp tạo nên Container Insights — stack monitoring tiêu chuẩn AWS cho EKS.

5 — IAM Security Migration (BB-1733)
Hiện tại Worker Node Role

CloudWatchAgentServerPolicy gắn trực tiếp vào eks-worker-role

Vấn đề: Mọi pod trên node đều có quyền ghi CloudWatch — vi phạm least privilege

Scope: Node-wide — bất kỳ container nào cũng có thể ghi log

BB-1733 migrate
Mục tiêu IRSA (per-pod)

IAM role point-fluent-bit-irsa-role chỉ trust

system:serviceaccount:amazon-cloudwatch:fluent-bit

Lợi ích: Chỉ Fluent Bit pod mới có quyền — đúng least privilege

Scope: Pod-scoped via OIDC federation

Lưu ý: Khi IRSA hoàn tất, CloudWatchAgentServerPolicy sẽ bị xóa khỏi worker node role. Nếu có pod nào khác đang phụ thuộc vào quyền này (ghi log trực tiếp vào CloudWatch), nó sẽ bị broken. Cần audit trước khi chuyển.

Flush 5s — Fluent Bit batch gửi log mỗi 5 giây. Grace 30s — trước khi shutdown, chờ 30s để flush hết buffer. hostNetwork: true — cần thiết để đọc /var/log trên host node. SQLite state DB — ghi nhớ vị trí đọc cuối cùng, tránh duplicate log khi pod restart.
