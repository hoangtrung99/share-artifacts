CloudWatch to S3 Architecture

Verup Project - Long-term Log Archival System

System Overview

Hệ thống archive CloudWatch logs sang S3 bucket để lưu trữ dài hạn (6-12 tháng) với chi phí thấp hơn so với CloudWatch Logs retention.

CloudWatch Log Groups (17 groups) ↓ Subscription Filters (filter_pattern: "") Kinesis Firehose Stream (kinesis_datadog) ↓ Buffer: 128 MB OR 900s (15 min) S3 Bucket (logs.bs-point-{env}-ex) ↓ Path: YYYY/MM/DD/HH/ S3 Lifecycle Policy ↓ Expiration: 180 days (DEV) / 365 days (STG) Delete

2. Subscription Filters

Terraform Resource aws_cloudwatch_log_subscription_filter.this

resource "aws_cloudwatch_log_subscription_filter" "this" { count = var.cloudwatch_to_s3_enabled ? length(var.kinesis_datadog_cloudwatch_logs_group) : 0 name = var.cloudwatch_log_subscription_filter_name role_arn = aws_iam_role.cloudwatchlogs_kinesis_role[0].arn log_group_name = element(var.kinesis_datadog_cloudwatch_logs_group, count.index) filter_pattern = "" # Forward ALL logs destination_arn = aws_kinesis_firehose_delivery_stream.this[0].arn distribution = "Random" }

Key Points:

  • filter_pattern = "" → Forward tất cả logs (không filter)
  • distribution = "Random" → Load balance across shards
  • IAM Role: cloudwatchlogs_kinesis_role với policy AmazonKinesisFirehoseFullAccess

3. Kinesis Firehose Stream

ACTIVE kinesis_datadog

resource "aws_kinesis_firehose_delivery_stream" "this" { count = var.cloudwatch_to_s3_enabled ? 1 : 0 name = var.kinesis_firehose_stream_name destination = "s3" s3_configuration { role_arn = aws_iam_role.kinesis_datadog_role[count.index].arn bucket_arn = data.aws_s3_bucket.log.arn buffer_size = 128 # MB buffer_interval = 900 # seconds (15 minutes) cloudwatch_logging_options { enabled = true log_group_name = "/aws/kinesisfirehose/kinesis_datadog" log_stream_name = "DestinationDelivery" } } }

Buffering Logic:

Trigger điều kiện: Firehose flush data sang S3 khi:

  • buffer_size đạt 128 MB, HOẶC
  • buffer_interval đạt 900 giây (15 phút)
  • → Cái nào đến TRƯỚC thì flush

Evidence từ AWS CLI:

$ aws firehose describe-delivery-stream --delivery-stream-name kinesis_datadog { "StreamName": "kinesis_datadog", "Status": "ACTIVE", "BufferSize": 128, "BufferInterval": 900, "S3Bucket": "arn:aws:s3:::logs.bs-point-dev-ex", "Compression": "UNCOMPRESSED" }

5. Firehose Monitoring Log Group

NOT CREATED MISSING

Vấn đề phát hiện:

Log group /aws/kinesisfirehose/kinesis_datadog được reference trong Terraform nhưng KHÔNG tồn tại trong AWS!

$ aws logs describe-log-groups --log-group-name-prefix "/aws/kinesisfirehose" { "logGroups": [] # ← EMPTY! }

Tác dụng:

  • Monitor Firehose delivery success/failure
  • Log errors khi delivery thất bại (IAM, S3 policy, network issues)
  • Track performance metrics (latency, batch size)

Tại sao Firehose vẫn hoạt động?

CloudWatch logging là OPTIONAL cho Firehose. Khi log group không tồn tại:

  • ✅ Core delivery vẫn hoạt động bình thường
  • ❌ Firehose KHÔNG thể ghi monitoring logs
  • ⚠️ Khi có lỗi delivery → KHÔNG có logs để debug

Solution: File log_group.tf đã được tạo để fix vấn đề này.

IAM Roles & Permissions

Role 1: kinesis_datadog_role

Purpose: Cho phép Firehose ghi data vào S3

Trust Policy: firehose.amazonaws.com

Permissions:

  • s3:PutObject - Ghi files vào S3
  • s3:GetBucketLocation - Xác định bucket region
  • s3:ListBucket - List objects trong bucket
  • s3:AbortMultipartUpload - Cleanup failed uploads

Role 2: cloudwatchlogs_kinesis_role

Purpose: Cho phép CloudWatch Logs forward data tới Firehose

Trust Policy: logs.ap-northeast-1.amazonaws.com

Permissions: AmazonKinesisFirehoseFullAccess (AWS managed policy)
