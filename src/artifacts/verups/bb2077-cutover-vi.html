BB-2077 — Thứ tự cắt chuyển DNS / SSL / WebSocket · API

Đổi domain nào sang domain nào, trạng thái before/after của từng thành phần, và thứ tự an toàn để cắt chuyển khi release verup mà không gây đứt traffic.

Người tạo: Masuda Người nhận: Shuku Phụ trách: Trung + Shuku (đều infra) Trạng thái: 未着手 / To Do Ngôn ngữ: VI · bản EN riêng
Tóm tắt 1 câu

Khi release verup, web customer/admin và kết nối API + WebSocket của frontend chuyển từ domain cũ *.coinbook.co.jp sang domain mới backseat-service.com. Nếu cắt sai thứ tự, site sẽ sập. Ticket này dùng để chốt thứ tự.

Quy tắc quyết định thứ tự

SSL phải sẵn sàng trên domain mới TRƯỚC khi flip DNS. Chính phần rủi ro của ticket đã ghi: flip DNS khi domain mới chưa có cert hợp lệ → toàn bộ HTTPS chết. Vậy thứ tự thực thi an toàn là SSL (chuẩn bị) → DNS (flip) → WebSocket/API (verify) — không phải DNS trước.

Chuỗi cắt chuyển

Thứ tự an toàn — SSL chuẩn bị trước, rồi DNS, rồi verify

Phase 0 Chuẩn bị — trước cửa sổ cắt
  1. Hạ DNS TTL xuống ~60s ở parent zone / NS-delegation, ≥ 24h trước cửa sổ để record cũ hết hạn nhanh.Đòn bẩy TTL nằm NGOÀI repo Terraform (record alias không có TTL) → verify live trên registrar.
  2. Provision / verify cert SSL cho *.backseat-service.com trên cả CloudFront (us-east-1) và ALB (ap-northeast-1), theo từng env.Đang bị chặn bởi gap cert ALB (xem blocker) → verify live trước cửa sổ.
  3. (Lớp app/frontend — BB-2069) Sửa 3 dòng production trong next.config.js sang domain mới, dựng prd pipeline, rồi rebuild + redeploy. Việc ở repo frontend; infra (Trung + Shuku) nắm timing so với lúc flip DNS.
Phase 1 Cửa sổ cắt chuyển
  1. Xác nhận SSL đã sẵn sàng trên edge mới (cert ISSUED + attached). Phải đúng trước khi flip DNS.
  2. Deploy frontend đã rebuild — host mới đã live và backend trả lời /websocket, /api, /app, /exchange.
  3. Flip DNS — trỏ record Route53 sang CloudFront mới. Host customer cắt api + app + websocket + exchange cùng lúc; admin (bo-*) riêng.
  4. Verify — dig trả về edge mới → bắt tay HTTPS → WebSocket live trên /websocket → smoke test login + đặt lệnh.
Phase 2 Sau cắt chuyển
  1. Bật redirect URL cũ (301/302) từ coinbook sang backseat (BB-2068).
  2. Drain — giữ host cũ còn phân giải tới khi bundle cũ đã cache ngừng gọi API/WebSocket cũ.
  3. Decommission domain coinbook theo kế hoạch xoá bỏ (BB-2047).

Chiến lược

Hướng đi là đổi domain; coinbook chỉ là cầu nối tạm

Hướng đi Option B — đổi domain

Frontend trỏ backseat-service.com; rebuild + redeploy; DNS domain mới phục vụ traffic. Căn cứ: BB-2047 (kế hoạch xoá coinbook), BB-2068 (redirect cũ→mới), và 2/3 frontend đã cấu hình sang backseat.

Chỉ là cầu nối Option A — giữ coinbook qua DNS

Repoint DNS service.coinbook.co.jp sang edge mới để bookmark còn chạy trong cửa sổ. Không miễn phí: cert edge mới là *.backseat-service.com, không phủ coinbook → phải import thêm cert coinbook + thêm alias.

Liên quan: BB-2047 domain policy (完了) · BB-2068 redirect cũ→mới · BB-2069 WebSocket/API cố định domain cũ (hạng mục c) · BB-1968 tài liệu thủ tục release.
Các fact live-AWS (inventory cert ALB, TTL NS-delegation) được đánh dấu "verify live" — kiểm tra read-only trong cửa sổ cắt chuyển.
