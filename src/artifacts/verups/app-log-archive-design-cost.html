Consideration 2

S3 storage class (cost-saving)

The app-logs lifecycle transitions to GLACIER_IR immediately (day 0), then expires — no STANDARD window. Firehose writes large objects (~40 MB per flush), far above the GLACIER_IR 128 KB minimum, so Instant Retrieval is the sweet spot: ~5× cheaper than STANDARD, still instant reads for incident debugging.

Why immediate (day 0), no STANDARD tier: the logs stay queryable in CloudWatch for ~1 year, so any hot / fast query hits CloudWatch — S3 is a pure cold archive. There is no need to pay STANDARD rates for a hot window in S3. GLACIER_IR has no minimum transition age, so a day-0 transition is valid.

Why audit-logs stays STANDARD: that bucket is dominated by tiny native objects (CloudTrail / SSM, mostly <128 KB). GLACIER_IR bills a 128 KB minimum per object plus a transition request — for small objects it raises cost. STANDARD wins there.

GLACIER_IR minimum storage duration is 90 days — safe here since retention ≥ 365 days.

At these volumes the buffer is time-triggered every 15 minutes (a 15-min slice is well under 128 MB), producing objects comfortably above the GLACIER_IR 128 KB minimum. Compression stays UNCOMPRESSED at Firehose because the CloudWatch→Firehose payload is already gzip level 6; setting GZIP would double-compress for no gain.

Monitoring: a delivery-error log group /aws/kinesisfirehose/app-log captures failures, plus Firehose CloudWatch metrics DeliveryToS3.Success and DeliveryToS3.DataFreshness (alarm-able for staleness).

Key takeaway. Using the measured volume of the single archived group, even at 7 years with immediate GLACIER_IR the app-log archive is only tens of dollars a month per environment — ≈ $36/mo at the dev-ex volume (2.6 GB/day compressed), ≈ $66/mo at the stg-ex volume (4.8 GB/day). Against a total infra bill in the thousands/mo (EKS + Aurora + Redshift + NAT), it is a rounding error — well under 1–3%. Storage class is the lever that keeps it there: GLACIER_IR is ~79% cheaper than STANDARD across a 7-year horizon.

V is the daily compressed archived volume of the single group /aws/containerinsights/point/application — S3 stores the gzipped payload, and both Firehose ingest and storage bill on it. Measured 2026-07-14 from CloudWatch IncomingBytes (8-day average, raw/uncompressed) divided by this group's empirical gzip ratio (~19× on a recent sample): dev-ex 49.7 GB/day raw → ~2.6 compressed · stg-ex 91.7 → ~4.8 · point-dev 66.9 → ~3.5 · point-stg 23.0 → ~1.2. prd not yet measured. The ~19× ratio reflects the highly repetitive Container Insights JSON; verify against real delivered objects after apply. Model is steady-state storage + ingest with immediate GLACIER_IR; excludes the tiny retrieval cost.

Second cost, separate path — audit logs

CloudTrail and SSM Session Manager write natively to the existing audit-logs.bs-point-<env> bucket — no Firehose, so no ingest fee. This work only raises that bucket's lifecycle expiration to the retention tier (dev 365 d · stg 730 d · prd 2557 d). The bucket stays on STANDARD ($0.025/GB-mo): the module defines no transition rule and its objects are tiny native records, so GLACIER_IR's 128 KB-per-object minimum would raise cost. Storage cost is therefore just steady-state size × $0.025 — no ingest term.

Takeaway — audit ≪ app-log. On STANDARD, projected audit-log storage is only cents to a few dollars per environment per month; the largest single line is prd at ~$10.5/mo (7-year tier, projected), and the projected steady-state total across every environment is ≈ $17/mo. That is still below the app-log archive's $36–$66 for a single environment above. (point stg is already at its 731-day target, so its retention change adds ~$0.) Audit stays cheap because it is low-volume, tiny native objects kept on STANDARD — no Firehose ingest, no Glacier small-object penalty.
