Redshift STG — Destroy & Recreate

env STG (point) account 471112755246 region ap-northeast-1 cluster point node ra3.xlplus ×2

The STG cluster was created in public subnets but the target config requires private subnets. Redshift cannot move a running cluster's subnet tier in place — so the cluster is destroyed and recreated. Because every attribute is set at CREATE time, the recreate sidesteps both blocking errors and lands encrypted, multi-AZ, and SSL-enforced from birth.

Root cause

Why in-place fixes fail

Error 1 — subnet group

Cannot remove an in-use subnet

SubnetAlreadyInUse: Cannot remove subnet-0973… because it is currently in use

The cluster node lives in public subnet-0973… (AZ 1a). Swapping the subnet group public → private must remove that subnet, which Redshift forbids while a cluster occupies it.

Error 2 — cluster modify

AZ relocation must be modified alone

InvalidParameterCombination: When a ModifyCluster AutoFailover operation is requested, no other modifications are allowed

Enabling availability_zone_relocation is treated as a standalone operation. Bundling it with encrypted, kms_key_id, and maintenance changes in one apply is rejected.

Conclusion: both errors are ModifyCluster-on-a-running-cluster constraints. A fresh CREATE sets private subnet group + encryption + AZ relocation + require_ssl all at once — so neither error can occur. KMS key/alias, parameter group, and snapshot schedule were already applied and are left untouched (they are dependencies, not destroyed).

After the recreate

Post-deploy & rollback

Post-deploy checks
  • Reload data — fresh cluster is empty; reload via migration/ETL, or set snapshot_identifier = "point-final-snapshot" before Phase 3 to restore (encrypts during restore).
  • require_ssl is active — every client must use SSL/TLS. Confirm the point app JDBC URL enables SSL; psql negotiates automatically.
  • Secrets / users — re-create app users + refresh secrets via db-user-manager/redshift-create-users.sh; master_user host is auto-updated by Terraform (endpoint expected unchanged). Master password unchanged.
  • Data check before & after — baseline svv_table_info + users before Phase 1, re-run after Gate 3 and diff. Fresh = empty (expected loss); restored = must match baseline.
  • Monitor ~30 min — cluster available, app connectivity, query success, snapshot schedule ACTIVE.
Rollback — the recovery source is the auto final snapshot point-final-snapshot (plus the manual point-prerecreate-*). If a gate fails before completion, restore that snapshot back into a subnet group that still contains the public subnets (revert Phase 2 first if already applied). After Gate 3 passes, no rollback is needed — do not delete the snapshots until the recreated cluster is validated.

Scope & Prerequisites

  • In scope: destroy + recreate of cluster point and the public→private swap of subnet group point, STG only.
  • Out of scope: KMS key/alias, parameter group (require_ssl=true), snapshot schedule — already applied; they are dependencies, not destroyed.
  • Data: this is a fresh recreate (empty cluster). To preserve data, use the Optional restore step below.
  • Downtime: cluster unavailable from start of Phase 1 until Gate 3 passes. STG downtime acceptable.
  • Master password unchanged — random_string.master_password is a dependency, not destroyed.
  • Blast radius: STG Redshift only.

0B Data baseline (before recreate)

Capture data + user + endpoint inventory BEFORE Phase 1 so the post-recreate state can be compared (fresh = empty, restored = must match).

bash · connect via Terraform-managed master_user secret
SECRET=$(aws secretsmanager get-secret-value --region ap-northeast-1 \
  --secret-id point/redshift/master_user --query SecretString --output text)
export PGPASSWORD="$(echo "$SECRET" | jq -r .password)"
RS_HOST="$(echo "$SECRET" | jq -r .host)"
RS_DB="$(echo "$SECRET" | jq -r '.dbname // "point"')"
RS_USER="$(echo "$SECRET" | jq -r .username)"

# Endpoint host baseline (to detect any change after recreate)
echo "$RS_HOST" > redshift-endpoint-before.txt

# Table inventory + row counts + size
psql -h "$RS_HOST" -p 5439 -U "$RS_USER" -d "$RS_DB" -At -F'|' \
  -c 'SELECT "schema","table",tbl_rows,size FROM svv_table_info ORDER BY "schema","table";' \
  > redshift-data-before.txt

# Summary: table count + total rows
psql -h "$RS_HOST" -p 5439 -U "$RS_USER" -d "$RS_DB" -At \
  -c 'SELECT count(*) AS tables, coalesce(sum(tbl_rows),0) AS total_rows FROM svv_table_info;' \
  | tee -a redshift-data-before.txt

# User inventory (app users are lost on a fresh recreate)
psql -h "$RS_HOST" -p 5439 -U "$RS_USER" -d "$RS_DB" -At \
  -c 'SELECT usename FROM pg_user ORDER BY 1;' > redshift-users-before.txt

Keep the three *-before.txt files for the after-comparison. svv_table_info row counts are estimates — add SELECT count(*) FROM <table>; for tables you must verify exactly.

1 Destroy the cluster

Keeps subnet group, KMS, parameter group, and random_string.master_password in state. With skip_final_snapshot=false, Terraform creates final snapshot point-final-snapshot on destroy.

bash · terraform/components/redshift
# Review: should destroy ONLY the cluster (+ cluster-attached resources)
../../terraform.sh --env stg plan -destroy -target='module.redshift[0].aws_redshift_cluster.this[0]'
# STOP if subnet group, KMS key, parameter group, or random_string is listed for destruction.

../../terraform.sh --env stg destroy -target='module.redshift[0].aws_redshift_cluster.this[0]'
# Type 'yes' when prompted.
Verify Gate 1 — STOP if not met
bash
aws redshift describe-clusters --region ap-northeast-1 --cluster-identifier point \
  --query 'Clusters[0].ClusterStatus' --output text
# Expected: error "ClusterNotFound"

aws redshift describe-cluster-snapshots --region ap-northeast-1 \
  --snapshot-identifier point-final-snapshot --query 'Snapshots[0].Status' --output text
# Expected: available  (wait if "creating")
Do not proceed without a usable backup snapshot.

3 Recreate the cluster

A full apply creates the cluster fresh inside the private subnet group. Because this is a CREATE (not ModifyCluster), encryption + KMS + AZ relocation + require_ssl are all set at birth — neither blocking error can occur.

#   module.redshift[0].aws_redshift_cluster.this[0]  => "+ create"

4B Data verification (after recreate)

Run after Gate 3. The master_user secret host was auto-updated by the Phase 3 apply, so this reconnects to the correct host automatically.

bash · compare against the baseline
SECRET=$(aws secretsmanager get-secret-value --region ap-northeast-1 \
  --secret-id point/redshift/master_user --query SecretString --output text)
export PGPASSWORD="$(echo "$SECRET" | jq -r .password)"
RS_HOST="$(echo "$SECRET" | jq -r .host)"
RS_DB="$(echo "$SECRET" | jq -r '.dbname // "point"')"
RS_USER="$(echo "$SECRET" | jq -r .username)"

# Endpoint diff — did the host change?
echo "$RS_HOST" > redshift-endpoint-after.txt
diff redshift-endpoint-before.txt redshift-endpoint-after.txt \
  && echo "ENDPOINT UNCHANGED" || echo "ENDPOINT CHANGED — non-master secrets refreshed in step 1"

# Same inventory query as the baseline
psql -h "$RS_HOST" -p 5439 -U "$RS_USER" -d "$RS_DB" -At -F'|' \
  -c 'SELECT "schema","table",tbl_rows,size FROM svv_table_info ORDER BY "schema","table";' \
  > redshift-data-after.txt
psql -h "$RS_HOST" -p 5439 -U "$RS_USER" -d "$RS_DB" -At \
  -c 'SELECT count(*) AS tables, coalesce(sum(tbl_rows),0) AS total_rows FROM svv_table_info;'

# Compare against baseline
diff redshift-data-before.txt redshift-data-after.txt \
  && echo "DATA IDENTICAL" || echo "DATA DIFFERENT (see diff above)"
Interpretation
  • Fresh recreate (default) — after is empty (no user tables) and app users are gone. Expected data loss → re-create users + reload in Post-Deploy.
  • Restored (snapshot_identifier set) — after MUST match baseline (DATA IDENTICAL). STOP if different, before switching traffic.

Post-Deploy Ops

  • Re-create DB users + refresh app secrets — fresh cluster has only master; app users (editor, viewer, editor_service, viewer_service) are gone. From terraform/components/redshift run cd ../../tool/db-user-manager && ./redshift-create-users.sh. It reads host from the Terraform-managed master_user secret and writes host + new passwords into point/redshift/{editor_service,viewer_service,editor_user,viewer_user} and the Spring Boot secret point/SPRING_DATASOURCE_HISTORICAL. Restored cluster → use redshift-update-passwords.sh or redshift-refresh-spring-boot-secret.sh instead.
  • master_user secret host is Terraform-managed — Phase 3 apply rewrites point/redshift/master_user host from the live endpoint, so it is always correct even if the endpoint changed. Only the non-master secrets (bullet above) need the tool.
  • Reload data (fresh only) — reload schema + data via migration/ETL. Skip if restored via snapshot_identifier (data + users already present).
  • require_ssl=true active from creation — every client must use SSL/TLS. psql (sslmode=prefer) negotiates automatically; confirm the point app JDBC URL enables SSL before pointing traffic back.
  • Monitor ~30 min — cluster available, app connectivity, query success, CloudWatch health. Confirm snapshot schedule point-redshift-snapshot-schedule is ACTIVE.
  • Append the live apply transcript to redshift-apply-log-stg.txt for the migration record.

Optional — Restore data from final snapshot

To keep current data instead of a fresh cluster, restore during Phase 3 (encrypts during restore, lands in private subnet group in one operation). Before Phase 3, set in tfvars/stg.tfvars:
hcl · tfvars/stg.tfvars
snapshot_identifier = "point-final-snapshot"
Then run Phase 3 as written. Leave this value as-is after a successful restore (snapshot_identifier is a create-time attribute; reverting to null may request a replacement, unless the module pins ignore_changes).

Rollback (by phase)

During/after Phase 1, before Phase 3 completes — the cluster no longer exists; restore the final snapshot back into a subnet group that still contains the public subnets (revert Phase 2 first if already applied):
bash · console or CLI restore
aws redshift restore-from-cluster-snapshot --region ap-northeast-1 \
  --cluster-identifier point \
  --snapshot-identifier point-final-snapshot \
  --cluster-subnet-group-name point \
  --publicly-accessible \
  --no-encrypted
# Returns the cluster to its pre-runbook state (unencrypted, public subnets).
After Gate 3 passes — no rollback needed. The point-final-snapshot and point-prerecreate-* snapshots are the recovery sources; do not delete them until the recreated cluster is validated in STG.
