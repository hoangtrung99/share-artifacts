Why is the for_cloudfront cert unused? CloudFront components look up the cert by domain *.backseat-service.com (Cybertrust cert), not *.{env}.backseat-service.com (ACM module cert). The two certs have different domains → data source selects the Cybertrust cert.

How Terraform references this cert
# frontend-customer/tfvars/dev-ex.tfvars:4 # (stg-ex, admin dev-ex, admin stg-ex are identical) cloudfront_certificate = "*.backseat-service.com" # frontend-customer/data.tf:1-4 # (frontend-admin/.../data.tf is identical) data "aws_acm_certificate" "this" { provider = aws.us # us-east-1 domain = var.cloudfront_certificate # "*.backseat-service.com" statuses = ["ISSUED"] } # frontend-customer/cloudfront.tf:16-20 viewer_certificate { acm_certificate_arn = data.aws_acm_certificate.this.arn # → points to the imported Cybertrust cert }

Terraform does not manage the lifecycle of this cert — it only looks up the ARN by domain. If the cert is deleted from ACM, terraform plan will fail because the data source won't find a match.

7 Certificate-Related Risks
!
Cybertrust cert expires 2026-10-29
Imported cert does not auto-renew. Manual re-import required before this date. If forgotten → CloudFront loses HTTPS viewer cert → entire site becomes inaccessible.
!
Terraform plan fails if cert is deleted
data "aws_acm_certificate" lookup will fail if the Cybertrust cert is removed from ACM. No one would be able to terraform plan for CloudFront components.
!
No audit trail
No one knows who imported the Cybertrust cert, when it was imported, or what the renewal process is. Not in terraform state → no history.
?
DEV for_cloudfront cert anomaly
The for_cloudfront cert in DEV us-east-1 was not found on AWS despite enable_certificate_for_cloudfront = true. Possibly deleted manually or terraform state drift.
