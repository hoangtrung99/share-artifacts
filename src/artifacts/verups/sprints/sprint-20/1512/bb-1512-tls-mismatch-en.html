HTTPS-only Origin: Forward Host Header

BB-1512 // CyberZeal compliance // CloudFront → ALB encryption

Switching origin_protocol_policy to https-only requires CloudFront to validate the ALB's SSL certificate. The wildcard cert *.backseat-service.com doesn't match the ALB DNS name. An initial Route53 custom domain approach also failed because RFC 6125 wildcards only match one DNS label. The final solution: forward the Host header so CloudFront validates the cert against the Host value instead of the origin domain name.

1 — The Problem (Two Layers)
Problem 1 ALB DNS doesn't match cert
CloudFront connects to the ALB using its auto-generated DNS name. Cert *.backseat-service.com doesn't match *.elb.amazonaws.com.
Origin domain: point-alb-xxx.ap-northeast-1.elb.amazonaws.com ALB cert SAN: *.backseat-service.com Match? NO → 502 Bad Gateway
Problem 2 Route53 custom domain also fails
Initial solution: create origin-alb.dev-ex.backseat-service.com pointing to the ALB. But the cert *.backseat-service.com still doesn't match — this is a 2-level subdomain.
Origin domain: origin-alb.dev-ex.backseat-service.com Wildcard cert: *.backseat-service.com Match? NO → * only matches 1 label
2 — RFC 6125: Wildcard Matching
RFC 6125 § 6.4.3 The Wildcard Rule
Per RFC 6125 (and RFC 2818), the * character in a wildcard certificate matches exactly one DNS label (the part between dots). It does not match across dot boundaries.
CertificateDomainMatch?Reason
*.backseat-service.com dev-ex.backseat-service.com Yes * = dev-ex (1 label)
*.backseat-service.com bo-dev-ex.backseat-service.com Yes * = bo-dev-ex (1 label)
*.backseat-service.com origin-alb.dev-ex.backseat-service.com No * cannot match origin-alb.dev-ex (2 labels, contains a dot)
*.backseat-service.com a.b.backseat-service.com No * cannot match a.b (2 labels)
AWS Documentation: "CloudFront verifies that the certificate was issued by a trusted CA and that the domain name in the certificate matches the domain name that you specified for Origin Domain Name, or the value of the Host header if you configured CloudFront to forward the Host header to the origin."
3 — Options Considered
Selected Forward Host Header
Keep domain_name as the ALB DNS name. Add Host to forwarded_values.headers for all ALB behaviors. CloudFront validates the cert against the Host header value instead of the origin domain.
  • Host = dev-ex.backseat-service.com → matches cert *.backseat-service.com
  • No new Route53 records needed
  • No new alb_origin_domain variable needed
  • ALB uses path-based routing → Host header doesn't affect routing
  • Cache key impact negligible (ALB behaviors serve dynamic content)
  • Simple rollback: remove Host from headers, revert protocol to http-only
Rejected Route53 Alias Record
Create origin-alb.{env}.backseat-service.com pointing to the ALB. Fails due to RFC 6125: this is a 2-level subdomain.
  • origin-alb.dev-ex.backseat-service.com = 2 DNS labels
  • Cert *.backseat-service.com only matches 1 label
  • Would require separate *.dev-ex.backseat-service.com cert → not feasible
  • Additional Route53 records + variables → more complexity

How the Solution Works
1
Client sends request to dev-ex.backseat-service.com → Host header = dev-ex.backseat-service.com
2
CloudFront forwards the Host header to the ALB origin (because Host is listed in forwarded_values.headers)
3
CloudFront uses the Host value as SNI in the TLS handshake instead of the ALB DNS name. SNI = dev-ex.backseat-service.com
4
ALB presents cert *.backseat-service.com. CloudFront validates: dev-ex.backseat-service.com matches *.backseat-service.com → TLS OK

    ALB-->>CF: 200 OK

Key insight: When forwarding the Host header, CloudFront uses the Host value (not the origin domain_name) for both SNI in the TLS handshake and certificate validation. This is an AWS-specific behavior, not standard TLS.

8 — Rollback Plan
Simple rollback — just reverse 3 types of changes
Since no new resources were created (no Route53, no variables), rollback only requires reverting code:
# cloudfront.tf (both customer and admin) origin_protocol_policy = "http-only" # from "https-only" origin_ssl_protocols = ["TLSv1", "TLSv1.1", "TLSv1.2"] # Remove "Host" from forwarded_values.headers: # /app/*: headers = ["user-agent"] # remove "Host" # /api/*: remove headers line # didn't exist before # /admin/*: remove headers line # didn't exist before # cloudfront_policy.tf (websocket) items = [Sec-WebSocket-Key, ...] # remove "Host"
Rollback advantage: No Route53 records to delete, no variables or data sources to restore. Just revert the protocol policy and remove Host headers → single commit.
