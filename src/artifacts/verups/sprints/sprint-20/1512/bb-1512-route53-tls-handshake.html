BB-1512 — CloudFront → ALB HTTPS-only — Rejected approach

Phương án Route53 tạo custom domain origin-alb.dev-ex.backseat-service.com trỏ về ALB, rồi dùng domain này làm CloudFront origin. Khi chuyển sang https-only, CloudFront sẽ validate TLS cert của ALB — nhưng cert wildcard *.backseat-service.com không match domain 2 cấp này theo RFC 6125.

01 — Tổng quan

Y tưởng của Route53 Approach

Mục tiêu: Đổi origin_protocol_policy từ http-only sang https-only để mã hóa traffic giữa CloudFront và ALB.

Vấn đề: CloudFront origin hiện dùng ALB DNS name (point-alb-xxx.ap-northeast-1.elb.amazonaws.com). Cert import trên ALB là *.backseat-service.com — không match ALB DNS.

Giải pháp đề xuất: Tạo Route53 Alias record origin-alb.{env}.backseat-service.com → ALB, dùng custom domain này làm CloudFront origin. Cert *.backseat-service.com sẽ match... nhưng không.

02 — DNS Setup

Route53 Record và CloudFront Config

Tạo một Route53 A record (Alias) trỏ về ALB, rồi cấu hình CloudFront dùng domain này làm origin:

Route53 Record
origin-alb.dev-ex.backseat-service.com
→
Alias Target
point-alb-xxx.ap-northeast-1.elb.amazonaws.com
→
ALB IPs
172.18.11.x, 172.18.12.x
CloudFront Origin Config (Terraform)
origin {
  domain_name = "origin-alb.dev-ex.backseat-service.com"
  origin_id   = "alb_origin"

  custom_origin_config {
    http_port              = 80
    https_port             = 443
    origin_protocol_policy = "https-only"
    origin_ssl_protocols   = ["TLSv1.2"]
  }
}
Lưu ý: Với https-only, CloudFront sẽ mở TLS connection tới origin. Nó sẽ gửi SNI (Server Name Indication) = domain_name của origin, và validate cert mà ALB trả về phải match domain này.

Diagram trên cho thấy rõ điểm thất bại: sau khi ALB trả về cert *.backseat-service.com, CloudFront cố validate xem cert này có match với SNI domain không — và nó không match.

1
User → CloudFront: TLS OK
User truy cập dev-ex.backseat-service.com. CloudFront có cert riêng (ACM US-East-1) cho domain này — TLS thành công.
2
DNS Resolution: OK
CloudFront resolve origin-alb.dev-ex.backseat-service.com qua Route53. Alias record trả về ALB IP.
A: origin-alb.dev-ex.backseat-service.com → 172.18.11.x
3
TCP Handshake: OK
CloudFront mở TCP connection tới ALB port 443. Three-way handshake thành công.
4
TLS ClientHello
CloudFront gửi ClientHello với SNI extension chứa tên origin domain.
SNI: origin-alb.dev-ex.backseat-service.com
5
ALB ServerHello + Certificate
ALB nhận SNI, chọn cert phù hợp nhất từ các cert đã import. Cert duy nhất là:
Subject: *.backseat-service.com — Issuer: External CA
6
CloudFront Validate Cert — FAIL
CloudFront kiểm tra: cert *.backseat-service.com có match origin-alb.dev-ex.backseat-service.com không?
Kết quả: MISMATCH. Gửi TLS Alert và đóng connection.
7
502 Bad Gateway
CloudFront trả về HTTP 502 cho user với error page mặc định.
04 — RFC 6125

Tại sao Wildcard Cert không match?

Theo RFC 6125 § 6.4.3, ký tự wildcard * trong certificate chỉ được phép match đúng 1 DNS label (phần giữa các dấu chấm).

Cert Pattern
* . backseat-service.com

* thay thế cho đúng 1 label — ví dụ: dev-ex, stg-ex, bo-dev-ex...

Test: 1-level subdomain
dev-ex . backseat-service.com
✓ * = dev-ex (1 label) → MATCH
Test: 2-level subdomain (Route53 approach)
origin-alb . dev-ex . backseat-service.com
✗ * = origin-alb? Nhưng còn .dev-ex → 2 labels → MISMATCH

*.backseat-service.com ≠ origin-alb.dev-ex.backseat-service.com

Vấn đề cốt lõi: Tên domain origin-alb.dev-ex.backseat-service.com có 2 labels trước phần base backseat-service.com. Wildcard cert chỉ cover được 1 label. Để match, cần cert *.dev-ex.backseat-service.com hoặc SAN entry chính xác.
Cert *.backseat-service.com MATCH
  • dev-ex.backseat-service.com
  • stg-ex.backseat-service.com
  • bo-dev-ex.backseat-service.com
  • anything.backseat-service.com
Cert *.backseat-service.com NOT MATCH
  • origin-alb.dev-ex.backseat-service.com
  • api.stg-ex.backseat-service.com
  • a.b.backseat-service.com
  • backseat-service.com (bare domain)
05 — Kết quả

502 Bad Gateway — Phương án bị loại bỏ

Kết luận

Route53 approach không khả thi với cert wildcard hiện tại *.backseat-service.com. Mọi request sẽ nhận 502 Bad Gateway do TLS handshake failure giữa CloudFront và ALB.

Khắc phục: Cần cert *.dev-ex.backseat-service.com (và *.stg-ex.backseat-service.com cho STG) — nhưng việc import nhiều cert làm tăng độ phức tạp vận hành.

Giải pháp thực tế: Dùng Forward Host Header — giữ nguyên ALB DNS làm origin domain, forward Host header để CloudFront dùng Host value (là dev-ex.backseat-service.com) cho SNI và cert validation. Cert *.backseat-service.com match 1-level subdomain này.

Forward Host Header (đã triển khai)

Thay vì đổi origin domain, thêm "Host" vào forwarded_values.headers của mỗi ALB behavior. CloudFront sẽ:

  1. Gửi SNI = Host header value = dev-ex.backseat-service.com
  2. ALB trả cert *.backseat-service.com
  3. CloudFront validate: * match dev-ex (1 label) → OK
  4. TLS handshake thành công, request được forward
