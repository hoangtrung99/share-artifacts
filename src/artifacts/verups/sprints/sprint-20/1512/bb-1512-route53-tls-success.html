Route53 + HTTPS-only
TLS Handshake Thành Công

Giả định DNS hợp lệ (1-level subdomain) — CloudFront → Route53 → ALB

Nếu Route53 record là origin-alb.backseat-service.com (1 cấp subdomain), cert wildcard *.backseat-service.com sẽ match và TLS handshake thành công. Trang này mô tả chi tiết từng bước của quá trình đó.

01 — DNS hợp lệ

Điều kiện để TLS thành công

Domain của origin phải là 1-level subdomain của backseat-service.com để match cert wildcard:

Cert Wildcard Pattern
* . backseat-service.com
DNS hợp lệ — 1-level subdomain
origin-alb . backseat-service.com
✓ * = origin-alb (đúng 1 label) → MATCH theo RFC 6125
Route53 Record (A Alias)
origin-alb.backseat-service.com
→
Alias Target
point-alb-xxx.ap-northeast-1.elb.amazonaws.com
→
ALB IPs
172.18.11.x, 172.18.12.x
Lưu ý: Trong thực tế BB-1512, các môi trường có Route53 zone riêng (dev-ex.backseat-service.com, stg-ex.backseat-service.com). Nếu muốn dùng Route53 approach, cần record trong zone gốc backseat-service.com hoặc cert riêng cho từng zone con.
02 — Sequence Diagram

Toàn bộ quá trình TLS 1.2 Handshake

sequenceDiagram
    participant U as User Browser
    participant CF as CloudFront
    participant DNS as Route53
    participant ALB as ALB

    Note over U,ALB: PHASE 1 - User to CloudFront

    U->>CF: HTTPS GET dev-ex.backseat-service.com/app/home
    Note over U,CF: TLS OK - CloudFront has ACM cert for *.backseat-service.com

    Note over CF,ALB: PHASE 2 - DNS Resolution

    CF->>CF: Origin domain = origin-alb.backseat-service.com
    CF->>DNS: A query: origin-alb.backseat-service.com
    DNS-->>CF: Alias to ALB - resolved to 172.18.11.x

    Note over CF,ALB: PHASE 3 - TCP 3-Way Handshake

    CF->>ALB: SYN to 172.18.11.x port 443
    ALB-->>CF: SYN-ACK
    CF->>ALB: ACK - TCP established

    Note over CF,ALB: PHASE 4 - TLS 1.2 Handshake

    CF->>ALB: ClientHello - TLS 1.2, SNI=origin-alb.backseat-service.com, cipher suites, random
    ALB-->>CF: ServerHello - chosen cipher TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, session ID, random
    ALB-->>CF: Certificate - subject *.backseat-service.com, chain, validity 2026-03-10

    Note over CF: CERT VALIDATION
    Note over CF: 1. Check expiry - OK, valid until 2027
    Note over CF: 2. Check chain - trusted CA - OK
    Note over CF: 3. Match SNI: *.backseat-service.com vs origin-alb.backseat-service.com
    Note over CF: 4. RFC 6125: * matches origin-alb = 1 label - MATCH

    ALB-->>CF: ServerKeyExchange - ECDHE P-256 params, signature
    ALB-->>CF: ServerHelloDone

    CF->>ALB: ClientKeyExchange - ECDHE public key
    CF->>ALB: ChangeCipherSpec
    CF->>ALB: Finished - encrypted verify hash

    ALB-->>CF: ChangeCipherSpec
    ALB-->>CF: Finished - encrypted verify hash

    Note over CF,ALB: TLS 1.2 Session Established - All traffic encrypted

    Note over CF,ALB: PHASE 5 - Application Data

    CF->>ALB: GET /app/home HTTP/1.1 Host: dev-ex.backseat-service.com
    ALB-->>CF: HTTP/1.1 200 OK - response body
    CF-->>U: HTTP/2 200 OK - forwarded response
03 — Chi tiết từng Phase

6 Phase của một request

01
User → CloudFront
Browser kết nối HTTPS tới CloudFront edge gần nhất. CloudFront có cert ACM (US-East-1) cho *.backseat-service.com. TLS giữa user và CloudFront luôn thành công.
02
DNS Resolution
CloudFront resolve origin domain qua Route53. Alias record trả về ALB IP address.
origin-alb.backseat-service.com → 172.18.11.x
03
TCP Handshake
CloudFront mở TCP connection tới ALB port 443. SYN → SYN-ACK → ACK. Nhanh vì cả hai đều ở AWS Tokyo region.
04
TLS Handshake
Phase quan trọng nhất. CloudFront gửi ClientHello với SNI = origin domain. ALB trả cert và CloudFront validate. Với 1-level subdomain, cert match.
05
Key Exchange
Sau khi cert được chấp nhận, cả hai thực hiện ECDHE key exchange để tạo shared secret. ChangeCipherSpec chuyển sang mã hóa. Finished message xác nhận cả hai có cùng key.
06
Application Data
HTTP request được gửi qua kênh mã hóa. CloudFront forward Host header gốc (dev-ex.backseat-service.com) để ALB route đúng.
04 — Cert Validation

4 bước kiểm tra certificate

Khi CloudFront nhận được cert từ ALB, nó thực hiện 4 bước validation:

Bước 1 Expiry check — Cert có hết hạn chưa? Valid: 2026-03-10 → 2027-03-10. OK Bước 2 Chain of trust — Cert có được sign bởi trusted CA? Verify chain lên root CA trong trust store. OK Bước 3 Hostname match — Subject/SAN có match SNI domain? *.backseat-service.com vs origin-alb.backseat-service.com. MATCH Bước 4 Revocation — Kiểm tra OCSP/CRL xem cert có bị thu hồi không. OK
Bước 3 là then chốt. CloudFront so sánh cert subject *.backseat-service.com với SNI value origin-alb.backseat-service.com. Vì origin-alb là đúng 1 DNS label, nó match wildcard *. Nếu là origin-alb.dev-ex.backseat-service.com (2 labels), bước này sẽ fail.
05 — SNI và Cert Selection

ALB chọn cert như thế nào?

Server Name Indication (SNI)

SNI là extension của TLS, nằm trong ClientHello message (gói tin đầu tiên). Nó cho ALB biết client muốn kết nối tới domain nào — quan trọng khi ALB host nhiều cert cho nhiều domain.

ClientHello SNI = origin-alb.backseat-service.com ALB logic Tìm cert match nhất với SNI → *.backseat-service.com ServerHello Gửi cert + ECDHE params về cho CloudFront CF validate * = origin-alb (1 label) → MATCH → tiếp tục key exchange
Sau khi TLS established

Mọi data giữa CloudFront và ALB đều được mã hóa bằng AES-128-GCM. HTTP request được forward qua kênh này: 

GET /app/home HTTP/1.1
Host: dev-ex.backseat-service.com
X-Forwarded-For: 203.0.113.50
X-Forwarded-Proto: https
Connection: keep-alive

ALB nhận HTTP request qua encrypted channel, route theo path rule, forward đến target group.

06 — Tóm tắt

Tại sao approach này khả thi về lý thuyết?

Origin domain origin-alb.backseat-service.com — 1-level subdomain Cert *.backseat-service.com — wildcard match 1 label SNI CloudFront gửi SNI = origin domain → ALB chọn đúng cert Validation * = origin-alb → MATCH → TLS thành công Kết quả HTTPS-only hoạt động — mã hóa end-to-end
Thực tế BB-1512: Approach này không áp dụng được vì các môi trường có Route53 zone riêng (dev-ex.backseat-service.com) nên record sẽ là origin-alb.dev-ex.backseat-service.com (2-level) — không match wildcard. Để dùng được, cần tạo record trong zone gốc backseat-service.com, nhưng điều này làm mất tính isolated giữa các môi trường. Vì vậy BB-1512 chọn Forward Host Header thay thế.
