Root Cause Code
AwsConfig.java line 36-38 — Khi accessKey và secretKey rỗng (luôn rỗng trên EKS vì không mount static credentials), code fallback sang InstanceProfileCredentialsProvider — class này bắt buộc gọi IMDS để lấy credentials.
AwsConfig.java — the root cause
public AWSCredentialsProvider getCredentialsProvider() {
    if (StringUtils.isEmpty(accessKey) || StringUtils.isEmpty(secretKey)) {
        // BUG: Hardcoded IMDS dependency
        return new InstanceProfileCredentialsProvider(false);
    }
    AWSCredentials creds = new BasicAWSCredentials(accessKey, secretKey);
    return new AWSStaticCredentialsProvider(creds);
}

The Fix — 1 Line of Code
AwsConfig.java — the fix
public AWSCredentialsProvider getCredentialsProvider() {
    if (StringUtils.isEmpty(accessKey) || StringUtils.isEmpty(secretKey)) {
        // FIX: Use chain that auto-detects IRSA before IMDS
        return DefaultAWSCredentialsProviderChain.getInstance();
    }
    AWSCredentials creds = new BasicAWSCredentials(accessKey, secretKey);
    return new AWSStaticCredentialsProvider(creds);
}
DefaultAWSCredentialsProviderChain thử lấy credentials theo thứ tự:
1. Env vars → 2. System properties → 3. Web Identity Token (IRSA) → 4. Profile file → 5. ECS container creds → 6. Instance Profile (IMDS)

Khi IRSA được cấu hình, chain dừng ở bước 3 — không bao giờ gọi IMDS.
