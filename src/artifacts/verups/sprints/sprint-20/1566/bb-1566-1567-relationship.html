BB-1566 và BB-1567 là cặp task tuần tự thuộc cùng hạng mục kiểm toán bảo mật CyberZeal mục 6 cho WAF Admin. Chúng giải quyết hai khía cạnh khác nhau của cùng một vấn đề: admin WebACL hiện không có rate limiting.

BB-1566 — 6.1 レートベースルールの有無
"Rate rule có tồn tại không?" → Tạo mới rate-limit rule group cơ bản ở chế độ đếm (count mode)
BB-1567 — 6.2 レート制限値の妥当性
"Rate limit có hợp lý không?" → Tinh chỉnh threshold, sửa scope-down, bật chế độ chặn (block mode)
BB-1567 không thể hoàn thành độc lập. Nó yêu cầu "xác minh tính hợp lý của rate limit" — nhưng nếu BB-1566 chưa apply thì không có rate limit nào để xác minh. BB-1567 cần baseline data từ count mode của BB-1566 (ít nhất 2-5 ngày).

6 Vấn đề cần xử lý
Scope-down path mismatch

BB-1566 dùng /admin/login và /admin/auth nhưng backend thực tế dùng /admin/v1/login và /admin/v1/gmo/authorization.

BB-1566 pathBackend pathKhớp?
/admin/login/admin/v1/loginCần xác minh
/admin/auth/admin/v1/gmo/auth...Cần xác minh
/api//api/OK
Cần xác minh thêm
  • CloudFront path rewriting — CloudFront có rewrite /admin/v1/* → /admin/* không? Nếu không → phải sửa scope-down path
  • Endpoint /admin/v1/register — Được whitelist trong WebSecurityConfig nhưng không tìm thấy controller mapping. Còn dùng không?
  • IP whitelist và rate-limit — Rate-limit đặt trước allow_all_ipv4 → IP whitelist vẫn bị rate-limit. Đúng ý đồ hay cần exclude?

8 Kế hoạch Rollback
Mức độ Hành động Thời gian Ảnh hưởng
Nhẹ rate_limit_block_enabled = false → apply ~5 phút Chỉ tắt block, giữ count mode để tiếp tục observe
Trung bình Revert commit Terraform → apply ~15 phút Xoá toàn bộ rate-limit rule group khỏi WebACL
Khẩn cấp AWS Console → Edit WebACL → Xoá rate rules ~2 phút Thao tác tay trực tiếp, cần đồng bộ Terraform state sau
Thiết kế an toàn: Biến rate_limit_block_enabled cho phép bật/tắt block mode mà không cần xoá rule. Đây là mức rollback nhẹ nhất — chỉ cần thay true thành false rồi apply. Count mode vẫn hoạt động nên không mất dữ liệu observe.
