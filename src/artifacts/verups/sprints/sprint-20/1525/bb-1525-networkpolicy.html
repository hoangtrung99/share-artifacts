BB-1525: Default Deny NetworkPolicy

CyberZeal Security Requirement — EKS Namespace default — 2026-03-05

Overview

Task BB-1525 implements default deny NetworkPolicy for the EKS default namespace, enforcing least-privilege networking as required by the CyberZeal security audit. Before this change, zero NetworkPolicies existed — all ingress/egress traffic was unrestricted.

Additive Model: Kubernetes NetworkPolicy is additive. The default-deny-all blocks everything, then each allow policy opens specific traffic. Policies are OR'd together — if any policy allows a connection, it is permitted.
Implementation

Files Changed (9 total)

  • terraform/components/eks/main.tf Enable VPC CNI Network Policy Agent (enableNetworkPolicy = "true")
  • point/base/networkpolicy-default-deny.yaml Default deny all ingress + egress for all pods
  • point/base/networkpolicy-allow-dns.yaml Allow egress to kube-system on UDP/TCP 53
  • point/base/networkpolicy-allow-internal.yaml Allow pod-to-pod ingress/egress on port 8080
  • point/dev-ex/networkpolicy-allow-ingress-vpc.yaml Allow ingress from VPC CIDR (172.18.0.0/16) on 8080, 8082
  • point/stg-ex/networkpolicy-allow-ingress-vpc.yaml Allow ingress from VPC CIDR (172.19.0.0/16) on 8080, 8082
  • point/dev-ex/networkpolicy-allow-egress-vpc.yaml Allow egress to VPC + external (7 rules, dev CIDR)
  • point/stg-ex/networkpolicy-allow-egress-vpc.yaml Allow egress to VPC + external (7 rules, stg CIDR)
  • k8s-manifests/bin/k8s_apply.sh Deploy script: apply all 5 policies in a single kubectl apply

Terraform Change

# terraform/components/eks/main.tf — vpc-cni addon "vpc-cni" = { addon_version = var.eks.addon_vpc_cni_version service_account_role_arn = aws_iam_role.vpc_cni_aws_node.arn configuration_values = jsonencode({ # NEW enableNetworkPolicy = "true" # NEW — enables eBPF enforcement }) # NEW }

Safety: Enabling the agent with zero NetworkPolicy resources has no effect — traffic flows normally until policies are applied.

Deploy Script (Single Atomic Apply)

# k8s-manifests/bin/k8s_apply.sh kubectl apply \ -f point/base/networkpolicy-default-deny.yaml \ # 1. Deny all -f point/base/networkpolicy-allow-dns.yaml \ # 2. Allow DNS -f point/base/networkpolicy-allow-internal.yaml \ # 3. Allow pod-to-pod -f $APP_DIR/networkpolicy-allow-ingress-vpc.yaml \ # 4. Allow VPC ingress -f $APP_DIR/networkpolicy-allow-egress-vpc.yaml # 5. Allow VPC egress

Critical: All 5 policies are applied in a single command to prevent a window where deny is active but allow rules haven't been created yet.

Key Findings

IRSA vs Pod Identity

Cluster uses IRSA (IAM Roles for Service Accounts) which authenticates via STS:443. The 169.254.170.2:80 metadata endpoint is for EKS Pod Identity — a different mechanism not used here. VPC CNI Network Policy does not block link-local addresses.

VPC Endpoints Impact

12 VPC Endpoints already exist (S3, SQS, SNS, STS, KMS, etc.). AWS service traffic stays within the VPC on port 443 via endpoint ENIs. The 0.0.0.0/0:443 rule covers both endpoint traffic and external API traffic. No separate rules needed.

Flow Logs Validation

24h VPC Flow Logs analysis confirmed: 99%+ outbound is HTTPS 443 to Cloudflare (exchange APIs). All codebase-identified endpoints map to observed traffic patterns. Zero rejected outbound traffic in current state — SG allows all egress.

Rollback Plan
