BB-1525 - PONTA Network Path Explainer

Direct path vs proxy path | updated 2026-03-06
Short answer: if stg truly runs through the PONTA proxy, pod-level runtime traffic does not require direct 28443 and 8443. In that case the pod only needs to reach 10.51.187.96:3128. Keep 28443/8443 only if you want direct-path diagnostics or a future fallback path.

1. Executive answer
Answer for STG

If stg is using the proxy branch at runtime, then pod-level traffic goes to 10.51.187.96:3128. Direct 28443/8443 are not mandatory for the runtime application path.

Common misconception

ponta.login-url is browser-facing redirect data, not outbound traffic from the pod. The real outbound calls come from if1507, if1511, and webIf.

Nuance: keeping 8443/28443 on stg may still be useful if the team wants direct-path probes, debugging, or an emergency fallback without changing policy again.

3. How the network path works

Direct path

  • The app target URL is :28443 or :8443
  • The HTTP client opens TCP directly to the destination host
  • Pod-level NetworkPolicy must allow the destination port itself
  • This matches dev today and prd in the current code state
→

Proxy path

  • The app still keeps logical target URLs at :28443 / :8443
  • But the HTTP client is configured with setProxy(proxy)
  • The pod opens TCP to proxy:3128
  • The proxy is the component that continues to the final PONTA host
Operational implication: pod-level NetworkPolicy always follows the pod's actual TCP path. If the pod talks to the proxy, allow 3128. If the pod talks directly to PONTA, allow 28443 and 8443.
4. Code evidence

login-url is redirect-only

Example controller snippet:

String redirectUrl =
        UriComponentsBuilder.fromUriString(pontaConfig.getLoginUrl())
                .queryParams(queryParams)
                .build()
                .toUriString();
log.info("redirect to ponta login screen, url: {}", redirectUrl);
response.sendRedirect(redirectUrl);

These locations build a URL and hand it to the browser/client. They do not perform server-side outbound calls to login-url.

if1507 / if1511 are real outbound calls

Service invocation plus the actual outbound POST:

String accessToken = pontaRequestUtil.if1507(secretCode);
String memberId = pontaRequestUtil.if1511(accessToken);

response =
        restTemplate.postForObject(
                pontaConfig.getIf1507Url(), requestEntity, String.class);

These flows use RestTemplate.postForObject(...), so they are true pod egress.

webIf is also real outbound traffic

Example from PontaBizInVokerApi:

response =
        restTemplate.postForObject(
                pontaConfig.getWebIfUrl(), requestEntity, String.class);
log.info("if001 response:{}", response);

Without proxy, this requires direct 8443. With proxy, the pod-level path becomes proxy:3128.

Proxy is enabled only for stg

The decisive proxy branch looks like this:

CloseableHttpClient httpClient;

if (point.common.constant.Environment.stg.name().equals(activeProfile)) {
    HttpHost proxy = new HttpHost(stgProxyHost, stgProxyPort);
    RequestConfig config = RequestConfig.custom().setProxy(proxy).build();
    httpClient =
            HttpClients.custom()
                    .setSSLSocketFactory(sslConnectionSocketFactory)
                    .setDefaultRequestConfig(config)
                    .build();
}

This is why stg uses proxy today, while dev and prd remain direct in the current code state.

5. NetworkPolicy impact
Mandatory runtime rules

STG: allow 10.51.187.96/32:3128

DEV: allow 8080 because the callback flow really uses it

PRD current code: allow direct 28443 and 8443

Optional supporting rules

Keeping 8443/28443 on stg is optional and should be justified by diagnostics, debugging, or an explicit direct-path fallback requirement.

6. PRD deployment notes
  • Do not copy the DEV 8080 rule into PRD as-is.
  • With the current code, PRD still behaves as a direct path and therefore needs 28443 and 8443.
  • If PRD is expected to use a proxy, NetworkPolicy is not enough. The code/profile handling must be changed because proxying is currently enabled only for stg.
  • Additional precheck: point-worker application-prd.yaml still has webIf-Url: #TBD.
Bottom line: NetworkPolicy should follow the pod's actual TCP path, not every logical URL that appears in configuration files.
