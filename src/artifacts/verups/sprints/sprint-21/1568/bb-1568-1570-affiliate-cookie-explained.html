Affiliate Cookie Tracking

BB-1568 • BB-1570 — CloudFront Cookie Forwarding Whitelist

Hệ thống affiliate tracking theo dõi người dùng đăng ký đến từ đối tác quảng cáo nào (Access Trade, ad-track.jp) để tính hoa hồng. Hoạt động theo mô hình cookie-based tracking — khi user click link affiliate, mạng quảng cáo set cookie trên browser. Khi user đăng ký tài khoản, backend đọc cookie để ghi nhận attribution.

01 Tổng quan
Affiliate Marketing là gì?
Affiliate marketing là hình thức marketing mà doanh nghiệp trả hoa hồng cho đối tác (affiliate) khi họ giới thiệu user đăng ký thành công. Để biết user đến từ affiliate nào, hệ thống sử dụng cookie tracking:

• User click link quảng cáo → affiliate network set tracking cookie trên browser
• User đăng ký → backend đọc cookie → ghi nhận đối tác nào giới thiệu
• Báo cho affiliate network → tính hoa hồng
Đối tác Mạng quảng cáo Cookie Name Domain DB ID
INTERSPACE Access Trade _atnct .coinbook.co.jp 1
CERES ad-track.jp adm_adtr_xuid .coinbook.co.jp 2

1
User click link Affiliate

URL chứa query param: ?atnct=xxx hoặc ?adm_adtr_xuid=yyy

2
Landing Page — Cookie được Set
Frontend (SignupSection.tsx) phát hiện query param và load tracking script:

• CERES: ad-track.jp/ad/js/lpjs.js → tự động set cookie adm_adtr_xuid

Mutual exclusion: chỉ cho phép 1 affiliate tại một thời điểm. Nếu có INTERSPACE param → xóa CERES cookie, và ngược lại.

3
Registration Request
User điền form đăng ký → POST /app/v1/user/register
Browser gửi Cookie header bao gồm _atnct=tracking-token

Đây là bước mà CloudFront phải forward cookie — nếu không có trong whitelist, CloudFront sẽ drop cookie trước khi đến backend.
4
Backend Parse Cookie
V1UserRestController.java:270-296
1. Kiểm tra: chỉ chạy với PERSONAL authority và first registration
2. Đọc raw Cookie header: request.getHeader("cookie")
3. Split theo ";" → được từng cookie
4. Với MỖI cookie.key: gọi affiliateInfoService.findOneByIdentify(key)
5. Nếu match → lưu affiliateInfoId + sessionId (giá trị cookie) + uuid vào bảng user
6. Break ngay khi tìm thấy match đầu tiên
point-app/invest/controller/V1UserRestController.java:270-296
5
Conversion Tracking
Backend trả response: { uuid, affiliateFrom }
Frontend (SignupCompleted.tsx) nhận và load conversion script:
• _atnct → load cv.min.js, gửi uuid làm verify param
• adm_adtr_xuid → load cv.js, gọi adtrack_cv.cv() với uuid làm buid

Báo cho affiliate network: "user này đã đăng ký thành công" → tính hoa hồng.
Sau đó: xóa cookie + localStorage (cleanup).

06 Vấn đề Coupling với CloudFront
Vấn đề cốt lõi
Trước thay đổi: forward = "all" — mọi cookie đều được forward. Backend query DB động nên tự động hoạt động với bất kỳ affiliate mới nào.

Sau thay đổi: forward = "whitelist" — tên cookie phải được khai báo tĩnh trong Terraform. Nếu thêm affiliate mới vào DB mà không cập nhật Terraform, CloudFront sẽ drop cookie trước khi đến backend → mất tracking (silent failure, không có lỗi).

Thêm một affiliate mới cần thay đổi 4 layer:

1
Database
INSERT vào bảng affiliate_info với tên cookie mới
2
Terraform
Thêm cookie name vào whitelisted_names của CloudFront
3
Frontend Landing
Thêm tracking script của affiliate network mới vào SignupSection.tsx
4
Frontend Conversion
Thêm conversion script vào SignupCompleted.tsx (x3 apps)
Nếu thiếu bất kỳ layer nào:
• Thiếu DB → backend không match được cookie → không ghi nhận (im lặng)
• Thiếu Terraform → CloudFront drop cookie → backend không nhìn thấy (im lặng)
• Thiếu frontend landing → cookie không bao giờ được set → không ghi nhận
• Thiếu frontend conversion → ghi nhận được nhưng affiliate network không biết → tranh chấp hoa hồng

Các giải pháp giảm coupling:

A. Giữ nguyên (Recommended)
Terraform comment cảnh báo về coupling. Vì không có admin API tạo affiliate, và 2 affiliate hiện tại ổn định từ đầu, rủi ro thấp.
+ Đơn giản nhất, không cần thay đổi thêm code
+ Least-privilege: chỉ cookie cần thiết được forward
- Silent failure nếu coupling bị quên
B. Tách behavior riêng
Tạo CloudFront behavior riêng cho /app/v1/user/register* với forward=all, giữ phần còn lại của /app/* với whitelist/none.
+ Không cần cập nhật Terraform khi thêm affiliate
- Config CloudFront phức tạp hơn
- Registration path vẫn forward tất cả cookies
C. Shared Config + CI
Lưu cookie names trong file config chung. CI check so sánh DB entries với config trước deploy.
+ Single source of truth + CI bắt lỗi
- Over-engineering cho 2 entries ổn định
- Cần thay đổi CI pipeline
07 Kiểm tra sau khi Apply
Bước 1: Kiểm tra affiliate trong Database
Trước và sau khi apply, verify bảng affiliate_info khớp với whitelist:
SELECT id, affiliate_name, identify FROM affiliate_info; -- Kết quả mong đợi: -- +----+----------------+----------------+ -- | id | affiliate_name | identify | -- +----+----------------+----------------+ -- | 1 | INTERSPACE | _atnct | -- | 2 | CERES | adm_adtr_xuid | -- +----+----------------+----------------+
Bước 2: Verify CloudFront config
aws cloudfront get-distribution-config --id "$CUSTOMER_DIST_ID" \ --query 'DistributionConfig.CacheBehaviors.Items[?PathPattern==`/app/*`].ForwardedValues.Cookies' \ --output json # Kết quả mong đợi: # [{ "Forward": "whitelist", # "WhitelistedNames": { "Quantity": 2, "Items": ["_atnct", "adm_adtr_xuid"] } }]
Bước 3: Test trên Browser (manual)
1. Mở DevTools → Application → Cookies
2. Thêm cookie thủ công: _atnct=test123 (domain dev)
3. Đăng ký user mới
4. Kiểm tra DB: SELECT session_id, affiliate_info_id, uuid FROM user WHERE email = '...'
5. Mong đợi: session_id = 'test123', affiliate_info_id = 1, uuid bắt đầu với cb_
Bước 4: Full Flow test (optional)
1. Navigate đến landing page với query param: ?atnct=1
2. Verify trong DevTools cookie _atnct đã được set bởi script
3. Hoàn tất registration
4. Verify trong Network tab: response có { uuid: "cb_...", affiliateFrom: "_atnct" }
5. Verify conversion script cv.min.js được load trên trang SignupCompleted
6. Verify DB attribution như bước 3
Negative test: Verify /api/* vẫn hoạt động bình thường không cần cookies:
curl -s -o /dev/null -w "%{http_code}" https://<domain>/api/v1/health → Mong đợi: 200
