Section 01

OAI — Origin Access Identity

OAI (Origin Access Identity) là cơ chế legacy của CloudFront để kiểm soát truy cập S3. AWS đã đánh dấu deprecated và khuyến khích chuyển sang OAC.

Cách hoạt động

  1. Tạo một "CloudFront user" đặc biệt — đây là OAI identity (VD: EXXXXXXXXXX)
  2. Cấu hình CloudFront distribution dùng s3_origin_config để gắn OAI với S3 origin
  3. S3 Bucket Policy grant quyền s3:GetObject cho OAI principal
  4. Khi user request → CloudFront tự động thêm OAI credential vào request gửi tới S3
Terraform — OAI Resource + CloudFront Origin
resource "aws_cloudfront_origin_access_identity" "this" {
  comment = "OAI for frontend"
}

origin {
  domain_name = aws_s3_bucket.this.bucket_regional_domain_name  # REST endpoint
  origin_id   = "s3_origin"

  s3_origin_config {
    origin_access_identity = aws_cloudfront_origin_access_identity.this.cloudfront_access_identity_path
  }
}
S3 Bucket Policy — OAI Principal
{
  "Sid": "AllowCloudFrontGetObject",
  "Effect": "Allow",
  "Principal": {
    "AWS": "arn:aws:iam::cloudfront:user/CloudFront Origin Access Identity EXXXXXXXXXX"
  },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*"
}
!
OAI chỉ hoạt động với S3 REST Endpoint (qua s3_origin_config). Nếu dùng S3 Website Endpoint + custom_origin_config thì không thể dùng OAI.
Section 02

OAC — Origin Access Control

OAC (Origin Access Control) là cơ chế hiện đại thay thế OAI. Thay vì tạo "user" đặc biệt, OAC yêu cầu CloudFront ký (sign) mỗi request bằng SigV4 trước khi gửi tới S3.

Cách hoạt động

  1. Tạo OAC resource với signing_behavior = "always" và signing_protocol = "sigv4"
  2. Gắn OAC vào CloudFront origin qua origin_access_control_id
  3. S3 Bucket Policy trust CloudFront service principal (cloudfront.amazonaws.com) kèm điều kiện SourceArn = Distribution ARN cụ thể
  4. Mỗi request từ CloudFront → S3 đều được ký bằng SigV4 → S3 verify chữ ký
Terraform — OAC Resource + CloudFront Origin
resource "aws_cloudfront_origin_access_control" "admin_s3" {
  name                              = "admin-s3-oac"
  origin_access_control_origin_type = "s3"
  signing_behavior                  = "always"    # Luon ky moi request
  signing_protocol                  = "sigv4"     # AWS Signature Version 4
}

origin {
  domain_name              = aws_s3_bucket.this.bucket_regional_domain_name  # REST endpoint
  origin_id                = "s3_origin"
  origin_access_control_id = aws_cloudfront_origin_access_control.admin_s3.id
  # KHONG can s3_origin_config block
  # KHONG can custom_header
}
S3 Bucket Policy — OAC (Service Principal + SourceArn)
{
  "Sid": "AllowCloudFrontOAC",
  "Effect": "Allow",
  "Principal": {
    "Service": "cloudfront.amazonaws.com"     <-- Service principal, KHONG phai user
  },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*",
  "Condition": {
    "StringEquals": {
      "AWS:SourceArn": "arn:aws:cloudfront::123456789:distribution/EYYYYY"
    }                                          <-- Chi cho phep 1 distribution cu the
  }
}
i
Tại sao OAC an toàn hơn OAI? OAI dùng 1 "user" identity có thể share giữa nhiều distribution. OAC dùng SourceArn condition → chỉ 1 distribution cụ thể được phép truy cập bucket. Ngoài ra, SigV4 signing có thể verify bởi cả S3 và CloudTrail.
Section 03 — Key Concept

S3 Website Endpoint vs REST Endpoint

Đây là điểm thường gây nhầm lẫn nhất. S3 cung cấp 2 loại endpoint hoàn toàn khác nhau để serve content. Việc chọn loại endpoint quyết định CloudFront origin config và khả năng bảo mật.

Website Endpoint

S3 Website Hosting Endpoint

Domain format
bucket.s3-website-ap-northeast-1.amazonaws.com
# hoac
bucket.s3-website.ap-northeast-1.amazonaws.com
  • Protocol: HTTP only — KHÔNG hỗ trợ HTTPS
  • Index redirect: Có — Tự động /path/ → /path/index.html
  • Error page: Có — Trả error document custom
  • CloudFront config: Phải dùng custom_origin_config
  • OAI/OAC support: KHÔNG
  • Bảo mật: Phải dùng custom header hoặc để public
✖
Không thể dùng OAI hay OAC. Đây chính là lý do Admin hiện phải dùng custom User-Agent header — một phương pháp không an toàn.
REST Endpoint

S3 REST API Endpoint

Domain format
bucket.s3.ap-northeast-1.amazonaws.com
# Terraform: bucket_regional_domain_name
  • Protocol: HTTPS — hỗ trợ đầy đủ TLS
  • Index redirect: KHÔNG — Cần CloudFront Function
  • Error page: KHÔNG — Trả XML error
  • CloudFront config: Dùng s3_origin_config (OAI) hoặc origin_access_control_id (OAC)
  • OAI/OAC support: CÓ — Cả OAI và OAC
  • Bảo mật: Block public access hoàn toàn, chỉ cho CloudFront truy cập
✔
REST endpoint cho phép block toàn bộ public access và dùng OAI/OAC. Đây là target cho BB-1473.

Section 08

Gotcha: Index Document Redirect

Khi chuyển từ Website Endpoint sang REST Endpoint, tính năng tự động redirect index.html sẽ mất. Đây là sự khác biệt quan trọng cần xử lý.

Website Endpoint (hiện tại)

Request → Response
GET /admin/dashboard/
  -> S3 auto-serves /admin/dashboard/index.html
  -> 200 OK

GET /admin/
  -> S3 auto-serves /admin/index.html
  -> 200 OK

REST Endpoint (mục tiêu)

Request → Response (KHÔNG có CF Function)
GET /admin/dashboard/
  -> S3 looks for key "/admin/dashboard/"
  -> 403 Forbidden (key not found)

GET /admin/
  -> S3 looks for key "/admin/"
  -> 403 Forbidden
!
Giải pháp: Thêm CloudFront Function (viewer-request) để rewrite URI. Khi URI kết thúc bằng /, tự động append index.html. Customer side đã có Lambda@Edge làm việc tương tự — có thể tham khảo.
Ví dụ CloudFront Function rewrite index.html
CloudFront Function (JavaScript runtime 2.0)
function handler(event) {
    var request = event.request;
    var uri = request.uri;

    // Neu URI ket thuc bang "/" -> append index.html
    if (uri.endsWith('/')) {
        request.uri += 'index.html';
    }
    // Neu URI khong co extension -> thu append /index.html
    else if (!uri.includes('.')) {
        request.uri += '/index.html';
    }

    return request;
}
