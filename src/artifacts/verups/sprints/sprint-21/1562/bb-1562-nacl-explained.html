1 Network ACL là gì?
Định nghĩa

Network ACL (NACL) là lớp tường lửa hoạt động ở tầng subnet trong AWS VPC. Mỗi subnet chỉ gắn với một NACL. NACL áp dụng cho toàn bộ traffic đi vào/ra khỏi subnet, bất kể resource nào bên trong.

Điểm khác biệt quan trọng nhất: Security Group là stateful, NACL là stateless.

Stateful Security Group

SG nhớ connection đã khởi tạo

Request vào → response tự động được allow ra

Không cần rule riêng cho return traffic

→ Scope: Instance/ENI level

Stateless Network ACL

NACL KHÔNG nhớ gì về connection

Mỗi packet được đánh giá độc lập

PHẢI có rule cho cả 2 chiều (inbound + outbound)

→ Scope: Subnet level (mọi resource)

Cách đánh giá rules

AWS đánh giá NACL rules theo thứ tự rule number thấp → cao. Khi match → dừng ngay (first match wins).

Packet đến → Rule 100? → Match → ALLOW/DENY → DỪNG Không match ↓ Rule 110? → Match → ALLOW/DENY → DỪNG Không match ↓ Rule 200? → ... ... Rule * → DENY (luôn luôn)

2 Tại sao Rule Number bắt đầu từ 100?
AWS Best Practice

AWS khuyến nghị dùng bội số 100 (100, 200, 300) thay vì tuần tự (1, 2, 3):

"We recommend that you leave gaps between the rule numbers (such as 100, 200, 300), rather than using sequential numbers (101, 102, 103). This makes it easier to add a new rule without having to renumber the existing rules."
— AWS Documentation

Bằng chứng: AWS tự dùng rule 100 cho default NACL — chính AWS thực hành đúng khuyến nghị của họ.

8 Default NACL — Deny All (Fail-Closed)
Trước BB-1562

Default NACL: Allow ALL

6 subnets đều dùng default → mọi traffic đều allow

Sau BB-1562

Default NACL: Deny ALL

Public NACL: Dedicated → 3 public subnets

Private NACL: Dedicated → 3 private subnets

Default NACL: 0 subnets → safety net cho subnet mới

Fail-closed design: Subnet mới được tạo ngoài VPC module sẽ tự động dùng default NACL (deny all). Đây là tính năng, không phải bug — buộc phải assign NACL đúng trước khi subnet hoạt động.

9 Defense-in-Depth — Cần cả 2 lớp
Lý doGiải thích
Compliance CIS AWS Benchmark 5.2 yêu cầu chặn ở tầng NACL, không chỉ SG. Đây là yêu cầu bắt buộc cho tổ chức tài chính.
Human Error Nếu ai đó vô tình thêm SG rule "allow SSH from 0.0.0.0/0" → NACL vẫn chặn. Port 22 < 1024 → không match ephemeral rule.
Coverage NACL bảo vệ toàn bộ subnet. SG chỉ bảo vệ resource được attach. Resource mới chưa có SG → NACL là lớp bảo vệ duy nhất.
Lưu ý RDP: Port 3389 nằm trong range 1024-65535 nên NACL rule 300 sẽ ALLOW. RDP được bảo vệ chính bởi Security Group (không có SG rule cho RDP từ 0.0.0.0/0). Đây chính là lý do cần cả 2 lớp.
