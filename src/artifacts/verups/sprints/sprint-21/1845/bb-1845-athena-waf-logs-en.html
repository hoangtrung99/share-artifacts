BB-1845: AWS Athena (WAF Log) Infrastructure

WAF access log query service for Verup project

Scope: INFRA only Env: dev-ex / stg-ex Refs: BB-1845
01 Overview

Objective

Build AWS Athena infrastructure to query WAF logs (all access logs including blocked, allowed, counted) from S3. A Worker (server-side, separate ticket) will use Athena to aggregate data hourly, store in MySQL, and display on BO admin panel.

Ported from Coinbook (UNYO-1074) to Verup with different naming conventions and architecture improvements: IRSA instead of worker node role, renamed table for accuracy.

04 Deploy Order

Deployment Order (dev-ex → stg-ex)

1

s3-waf-logging — Add lifecycle rule

Safe, only adds a new rule. Does not affect existing WAF logs. Parallel OK

2

waf-athena — Create Glue + Athena resources

Entirely new resources, no impact on any existing service. Requires terraform init first time. Parallel OK

3

eks — Add IAM policy to IRSA role

Inline policy added to IRSA role. Takes effect immediately, no scale down/up needed. Parallel OK

4

frontend-customer — Remove CloudFront geo restriction

Run last after verifying WAF country_restrict is working. CloudFront invalidation takes a few minutes.

Steps 1-3 can run in parallel as they are all safe and cause no downtime. Step 4 should run last after confirming WAF rules work correctly.

06 WAF Rules & DEV/STG Testing

Note: country_restrict does not fire on DEV/STG

On DEV/STG, is_public = false so block_except_allow_ipv4 (priority 0) is active. This rule blocks all IPs not in the allowlist before country_restrict (priority 1) is evaluated.

flowchart TD
    REQ["Incoming Request"] --> P0{"Priority 0\nblock_except_allow_ipv4\n(is_public=false)"}
    P0 -->|"IP NOT in allowlist"| BLOCK0["BLOCK\nterminatingruleid =\nblock_exepct_allow_ipv4"]
    P0 -->|"IP in allowlist\n(team members)"| P1{"Priority 1\ncountry_restrict\nallow: JP,CN,HK,US"}
    P1 -->|"Country NOT in list\n(e.g. VN without VPN)"| BLOCK1["BLOCK\nterminatingruleid =\ncountry_restrict"]
    P1 -->|"Country in list\n(JP/US via VPN)"| REST["Priority 2-12\nBPO, GMO, rate limits..."]
    REST --> P13["Priority 13\nallow_all_ipv4 ALLOW"]

    BLOCK0 -.->|"Logged in WAF"| S3["S3 WAF Logs"]
    BLOCK1 -.->|"Logged in WAF"| S3
    P13 -.->|"Logged in WAF"| S3

Result: On DEV/STG, most requests are blocked by block_except_allow_ipv4 (priority 0), not country_restrict. Athena queries filtering terminatingruleid = 'country_restrict' will return little or no data.
Test TypeDEV/STGPRDExplanation
Query all WAF logs OK OK All requests are written to S3
Query action = 'BLOCK' OK OK Data available from block_except_allow_ipv4
Query terminatingruleid = 'country_restrict' Limited OK DEV/STG: rule 0 blocks first. PRD: is_public=true so rule 0 doesn't exist
When PRD is deployed (is_public = true): block_except_allow_ipv4 will not exist → country_restrict becomes the first rule evaluated → Athena queries for country_restrict will have full data.
