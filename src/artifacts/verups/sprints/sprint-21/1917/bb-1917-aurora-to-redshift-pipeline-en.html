BB-1917: Aurora → Redshift ETL Pipeline

Eliminate direct Redshift writes — replace with automated Glue ETL pipeline from Aurora MySQL

This task builds an automated data sync pipeline from Aurora MySQL to Redshift via AWS Glue ETL. The goal: App workers (point-worker, point-mmh) write only to Aurora — Glue periodically extracts data, converts to Parquet on S3, then bulk-loads into Redshift via COPY. Consumers are unaffected — Admin reports, AML detection still read from Redshift as before.

1 — Problem Overview
Core Problem

The application currently uses HistoricalTransactionManager to issue direct INSERT statements into Redshift every second per symbol. There are 7 Archiver Workers writing concurrently.

Redshift is not OLTP

Columnar store optimized for analytics, not per-second small writes. Each INSERT consumes disproportionate resources.

Tight Coupling

App bugs or failed deployments can corrupt Redshift data. Hard to rollback since both systems are tightly bound.

Separation of Concerns

Operational app code should not know about the historical warehouse. The warehouse should be a consumer, not a producer.

Step-by-Step Timing
  • EventBridge trigger → Glue StartJobRun: <1s
  • Glue cluster cold start: 30–60s
  • Spark read + write: 1–5 min (varies by table size)
  • Redshift COPY: 10–60s
  • Total lag: ~3–8 min per table
Incremental Load (Bookmarks)
  • Run 1: SELECT full table → save bookmark id MAX
  • Run 2+: WHERE id > bookmark → only new records
  • Tables with updated_at → catches UPDATEs too
  • Tables without PK/timestamp → full reload each time (expensive)

Security Group Rules Required
  • Aurora SG: Add ingress from glue-connection-sg on port 13306
  • Glue SG: Self-referencing ingress (required for Glue ENI inter-communication)
  • Glue SG: Egress all (Glue needs to reach S3, STS, Secrets Manager)
Existing VPC Endpoints
  • S3 Gateway — Glue S3 traffic avoids NAT costs
  • STS — AssumeRole for Glue service
  • Secrets Manager — Retrieve Aurora credentials
  • Missing: com.amazonaws.ap-northeast-1.glue (may need NAT fallback)
Custom port 13306 — Aurora uses a non-standard MySQL port (not the default 3306). The Glue Connection JDBC URL must specify the correct port: jdbc:mysql://aurora-endpoint:13306/point. Incorrect port will cause Connection refused during Glue Connection test.
IAM Role Design Details
Glue Service Role (glue-etl-service-role-dev-ex)

Principal: glue.amazonaws.com

Permissions:
• AWSGlueServiceRole (managed)
• secretsmanager:GetSecretValue for Aurora credentials
• s3:*Object, s3:ListBucket on staging bucket
• kms:Decrypt/Encrypt/GenerateDataKey* for S3 SSE
• ec2:*NetworkInterface* for VPC ENI creation
Redshift COPY Role (redshift-s3-copy-role-dev-ex)

Principal: redshift.amazonaws.com

Permissions:
• s3:GetObject, s3:ListBucket on staging bucket (read-only)
• kms:Decrypt for S3 SSE

Must be attached to Redshift cluster via aws_redshift_cluster.iam_roles.
