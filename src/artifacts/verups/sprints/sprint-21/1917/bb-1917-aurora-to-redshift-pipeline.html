BB-1917: Aurora → Redshift ETL Pipeline

Redshiftの直接操作をなくす件：インフラタスク — loại bỏ ghi trực tiếp Redshift, thay bằng Glue ETL pipeline

Task này xây dựng pipeline tự động đồng bộ data từ Aurora MySQL sang Redshift thông qua AWS Glue ETL. Mục tiêu: App (point-worker, point-mmh) chỉ ghi vào Aurora — Glue định kỳ extract, chuyển Parquet ra S3, rồi COPY vào Redshift. Consumer không đổi — Admin report, AML detect vẫn đọc Redshift như hiện tại.

1 — Tổng quan vấn đề
Vấn đề cốt lõi

Hiện tại App dùng bean HistoricalTransactionManager để phát INSERT trực tiếp vào Redshift mỗi giây / mỗi symbol. Có 7 Worker đang ghi đồng thời.

Redshift không phải OLTP

Columnar store tối ưu cho analytics, không phải ghi nhỏ lẻ mỗi giây. Mỗi INSERT tốn nhiều resource.

Tight coupling

Bug App hoặc deploy lỗi có thể corrupt data Redshift. Rollback khó vì 2 hệ thống dính chặt vào nhau.

Vi phạm SoC

App operational không nên biết gì về warehouse lịch sử. Warehouse là consumer, không phải producer.

2 — As-Is vs To-Be
As-Is (hiện tại)
To-Be (sau BB-1917 + BB-1918)
  • App dùng 2 datasource: Aurora (master) + Redshift (historical)
  • HistoricalTransactionManager INSERT trực tiếp vào Redshift
  • 7 Archiver Worker ghi Redshift mỗi giây/symbol
  • Lỗi App → corrupt data Redshift
  • Redshift chịu tải OLTP (INSERT nhỏ lẻ)
  • App chỉ ghi Aurora — 1 datasource duy nhất
  • Glue ETL batch 5 phút extract Aurora → Parquet → S3
  • Redshift COPY từ S3 (bulk load — nhanh x100)
  • Lỗi App chỉ ảnh hưởng Aurora, Redshift độc lập
  • Redshift chỉ phục vụ analytics (đúng công nghệ)
BB-1917 (task này) lo infra side: S3, Glue, IAM, SG, triggers. BB-1918 (sibling) lo app side: sửa 7 Worker bỏ INSERT Redshift, chỉ ghi Aurora. Hai task chạy song song, merge cùng lúc.

Timing từng bước
  • EventBridge trigger → Glue start: <1s
  • Glue cluster cold start: 30-60s
  • Spark read + write: 1-5 min (tuỳ bảng)
  • Redshift COPY: 10-60s
  • Tổng lag: ~3-8 phút cho mỗi bảng
Incremental load (Bookmarks)
  • Lần 1: SELECT toàn bộ → lưu bookmark id MAX
  • Lần 2+: WHERE id > bookmark → chỉ data mới
  • Bảng có updated_at → bắt được UPDATE
  • Bảng không có PK/timestamp → full reload (tốn kém)

SG rules cần thêm
  • Aurora SG: ingress from glue-connection-sg port 13306
  • Glue SG: self-referencing ingress (Glue ENI inter-comm)
  • Glue SG: egress all (Glue can reach S3, STS, Secrets Mgr)
VPC Endpoints hiện có
  • S3 Gateway — Glue S3 traffic không tốn NAT
  • STS — AssumeRole cho Glue service
  • Secrets Manager — Lấy Aurora credentials
  • Chưa có: com.amazonaws.ap-northeast-1.glue
Port 13306 — Aurora dùng custom port (không phải 3306 mặc định). Glue Connection JDBC URL phải dùng đúng port: jdbc:mysql://aurora-endpoint:13306/point. Nếu sai port → Connection test fail với Connection refused.
