BB-1917 — 3-solution comparison • coinbook/bse crypto exchange • april 2026

Executive Summary

Problem: 7 workers perform direct JDBC INSERTs into Redshift every second per trading symbol, pushing CPU to 99.08%. The initiative BB-1917/BB-1918 aims to replace these with an automated pipeline.

Verdict: After 12 parallel research threads (web research, codebase analysis, infra audit, cost modeling, risk assessment, regulatory review), S3 Export + Redshift COPY is recommended as the primary solution.

CRITICAL: The DELETE Problem. Current archive workers DELETE from Aurora after archiving to Redshift. With Zero-ETL, DELETEs replicate to Redshift — destroying historical data in both databases. Requires fundamental architecture change: stop deleting, or use soft-delete pattern. Affects 4 of 7 workers.
CRITICAL: Continuous write pressure. Zero-ETL adds constant CDC writes to Redshift. With CPU already at 99.08%, this may worsen the problem rather than solve it. Batch approaches (Glue, S3+COPY) give Redshift breathing room between loads.

9 — Recommendation

Primary: S3 Export + Redshift COPY

  1. Addresses the root cause — replaces per-second JDBC INSERTs with batch COPY
  2. Lowest risk — atomic, auditable, easy rollback, no Aurora changes
  3. Cheapest — ~$4-10/month vs $13-442 (Glue) or $325+ (Zero-ETL)
  4. Fastest to implement — 5-8 days vs 10-17 (Glue) or 11-16 (Zero-ETL)
  5. Best audit trail — S3 files provide immutable record for JFSA compliance
  6. Easiest migration — table by table, revert at any point
  7. Lowest vendor lock-in — pattern works on any cloud

Secondary (Future): Zero-ETL

Right long-term direction, but: service needs maturity (GA late 2023), DELETE replication conflict needs resolution, Aurora must be upgraded (3.04 LTS ends Oct 2026). Revisit when risks are better understood.

NOT Recommended: Glue ETL

Overengineered for simple table replication. Spark ETL ($211-442/mo) when Python Shell ($7-13/mo) suffices. EST 17 days when S3 Export needs 5-8. If Glue is chosen anyway, use Python Shell, NOT Spark.
