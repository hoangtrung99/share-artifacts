## Risks / points to be careful about

1. **IP address shortage** — ALB can go down if a subnet has fewer than 8 available IPs. STG VPC is a **/24** (`10.51.187.0/24`) with **/26** private subnets (`10.51.187.64|128|192/26`) — far tighter than DEV's /16. Verify ≥7-8 free IPs/subnet before vpc (#8) and the ALB SG cutover (#10).
2. **Ponta connection check** — keep existing VGW routing + CoreDNS config intact. ⚠ The vpc (#8) NACL/route-table migration on az2/az4 will **drop two unmanaged routes** on `rtb-0241362c6cf0dbaa2`: `172.19.0.0/16 → pcx-0ce5c02bb35a7bd32` (verup-STG peering) and `10.50.0.121/32 → vgw-0c33e00d8d13702e0` (Ponta far-end host route). Re-add post-apply or confirm sunset before the window.
3. **Frontend resources (STG-only)** — STG customer-frontend has **manually-created proxy + OAuth resources** that must remain intact. The frontend-customer (#38) apply must not clobber them. (PRD does not have this setup.)
4. **WAF deployment impact** — waf-customer (#39) deployment causes a maintenance interruption; banner ≥6h ahead, dedicated window. Expect the post-apply `untaint` recovery on `country_restrict`/`core_rule_set`/`rate_limit_count` (apply → untaint those 3 → re-apply).
5. **IAM access restriction** — confirm office / ESS source IPs before infra/iam (#1); `custodian-AdministratorRole` is breakglass — import pre-existing custodian roles/policies in order to avoid lockout.
6. **Code fixes block the plan** — eks `cluster_node_ami_type` (#104), iam viewer data-source (#105), frontend-customer ACM ambiguity (#106) must be merged to `release/verup` before the eks / iam / frontend-customer windows, or `terraform plan` exits 1 at those rows.
7. **Multi-NAT + stateful destructive** — STG `single_nat_gateway=false` → init/eip (#0b) creates 3 EIPs and must precede vpc (#8). The stateful tier is destructive as in DEV: aurora port 3306→13306 + secret rotate (#19), redshift KMS dance + reboot (#18), elasticache encryption replace = **data wipe** (#17). CTO/DBA/analytics sign-offs + scale pods to 0.
8. **EKS** — pin `1.31` (NOT 1.34); IRSA-first + `before_compute` (CNI deadlock fix); RBAC bindings before the API flip; Stage-1 (#21) and Stage-2 (#21b) run in **separate windows**.

## Coordination with app

1. **ci/cd** — (a) provide env resource values (distribution id / S3 bucket name etc.) for the pipeline in advance; (b) create new cicd secrets if needed.
2. **eventbridge** — (a) after infra/iam is deployed, app can start the eventbridge part; (b) stop necessary eventbridge rules before the real release (prevent unexpected data manipulation).
3. **shut down backend before release** — after turning off eventbridge, scale all backend pods to 0 (they might get restarted during the deploy; shut down to avoid interruption to other tasks).
4. **data migration** — (a) after infra/iam is deployed, app can start DMS preparation (console operation, admin role needed); (b) after ec2-data-transfer is set up, notify app to test their data-migration shell scripts.
