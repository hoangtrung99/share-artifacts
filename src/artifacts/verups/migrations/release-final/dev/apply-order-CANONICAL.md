## Rationale

The order is driven by a hard prerequisite spine, not by the wave names in older drafts. `infra/iam` and `infra/audit` go first because they materialize the 6 custodian roles and the shared `s3-access-logs.bs-point-dev` bucket that the 5 S3 components and 3 WAF components depend on. `vpc` precedes everything network-touching and is lockout-safe to run from the SSM bastion — the private bastion’s subnet moves to the new private NACL which preserves all intra-VPC + ephemeral (the SSM path), new NACLs get rules before any subnet associates, and the default NACL flips to deny-all last (the single destroy is a state-record migration of the default NACL, not a real delete). `security_group` is the largest blast radius: the ALB SG swap is controller-driven via `kubectl apply` of the edited ingress, so a naive `terraform destroy` of `alb-sg` would hit a DependencyViolation against three live ALB ENIs — it is sequenced with the aurora `3306→13306` mysql-sg edits in the same maintenance window. The stateful tier (elasticache replace, redshift KMS+SSL reboot, aurora port flip + password rotation) is gated behind security_group and clustered into the Sun-night window because each carries real downtime; the GROUND-TRUTH inventory corrected the stale "greenfield" assumptions (aurora and redshift already exist and are in state, redshift is already encrypted — the work is a KMS swap, not enabling encryption). The EKS block is the trickiest sequencing: the auth-mode bridge must precede the version ladder, but its API-mode access entry references `point-cd-runner-role`, which `ec2-cd-runner` creates — so the auth-bridge is gated on either ec2-cd-runner landing first or importing that role, and on the Bug B fix (`named_user` must be the real dev user `bs-developer`, not the leaked stg `bs-operator`, or the flip to API auth locks everyone out). The version ladder must step one minor at a time (the module passes the version straight to the API, which rejects multi-minor jumps), and the five S3 components wait on EKS materializing `point-app-irsa-role`. Finally, `waf-customer` is deliberately the deferred tail: it is the only customer-facing maintenance interruption, so it is isolated to its own Sunday window after everything else is green.
