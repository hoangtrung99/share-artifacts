## STEP 0 — Identity & backend guard (run before EVERY apply, not just once)

The single worst outcome is applying into the **wrong account**: legacy-dev `845131030484` shares the CIDR `172.18.0.0/16` with the target, so a wrong-profile apply looks plausible and is maximally confusing. The only built-in guard is implicit (the state bucket `tfstate.bs-point-dev` is owned by 905418018638, so a wrong-profile remote-backend `init` fails) — **and that guard disappears if terraform silently falls back to a local backend.** So this check is mandatory before each component apply:

```bash
# 1. Confirm the account
aws sts get-caller-identity --query Account --output text   # MUST print 905418018638

# 2. Confirm terraform will use the S3 backend (NOT local) — read the wrapper's banner
../../terraform.sh --env dev init 2>&1 | grep -E 'Backend:'  # MUST print "Backend: s3", never "local"
```

If `init` ever prints `Backend: local`, **STOP**: a stale `backend.tf` or `tmp/dev/<component>/.cxr_config` from a prior killed run is poisoning the backend — clean it (`find terraform/components -name backend.tf` + remove stale; `rm -rf terraform/tmp/dev/<component>`) and re-init. A local-backend apply runs against empty state and mass-creates resources into whatever account the profile points at.

**Recommended hardening (one-time code change, optional but cheap):** add `data.aws_caller_identity.current` + a `lifecycle.precondition`/`check` asserting `account_id == "905418018638"` on the foundational components — it is the only account-guard that survives the local-backend fallback.

## RECOVERY PRIMITIVES (apply to any step)

- **Killed apply (SIGKILL / OOM / network):** the wrapper's signal trap does not cover SIGKILL, so the DynamoDB lock (`point_tfstate_lock`) stays held → next apply fails `Error acquiring the state lock`. Run **`terraform force-unlock <LOCK_ID>`** (id is in the lock error), then re-plan + re-apply.
- **Corrupted / half-written state:** the state bucket `tfstate.bs-point-dev` has **versioning enabled** → restore the pre-apply version: `aws s3api list-object-versions --bucket tfstate.bs-point-dev --prefix dev/<component>.tfstate` → `get-object --version-id <last-good>` → copy back. Last resort.
- **`AlreadyExists` on a `+ create`:** a resource exists live but isn't in this component's state (pre-existing, or an orphan from an earlier killed apply that created it before writing state). Recover with **`terraform import <address> <id>`**, then re-plan. Most exposed: S3 buckets (global names), immutable-named CloudWatch log metric filters / alarms, security groups.
- **Backend fell back to local:** see STEP 0 — clean the stale `backend.tf` / `tmp/dev/<component>` and re-init with the remote backend before doing anything else.
