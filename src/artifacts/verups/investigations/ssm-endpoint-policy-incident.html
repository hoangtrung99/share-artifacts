Infra Incident · point stg · account 471112755246

Two boxes went dark on SSM.
The box was fine. The policy said no.

On 2026-06-30 two live EC2 instances — hulft (HULFT file transfer / NFS) and ponta-proxy (Squid egress) — dropped off Systems Manager and stayed ConnectionLost for 8 days. Every early guess was wrong: not the box, not the network, not the clock, not credentials, not a dead agent. One line settled it — the SSM agent's own log.

hulft i-042325ebdb8991aa9 ponta-proxy i-0ce6fa785d00e57a0 vpc-08888557d0bd0cead investigated 2026-07-08 fix PR #135
Root cause

The endpoints Terraform apply on 06-30 rewrote the VPC endpoint policies for ssm / ssmmessages / ec2messages. The new aws:PrincipalArn allowlist dropped ponta-proxy-role and point-hulft-role.

Agent talks to the endpoint. Endpoint checks the role against the list. Role not on list → AccessDenied on every UpdateInstanceInformation and GetMessages → PingStatus freezes, agent retries forever. Box, clock, creds, agent: all healthy the whole time.

04 Why exactly these two

The allowlist is keyed by role name

The endpoints component builds each endpoint policy from a role_endpoint_access map. Migrated roles are in it. Two legacy point-stg boxes that pre-date the migration were not — so the apply locked them out and no one else.

On the allowlist → stayed Online

Migrated / managed roles present in the stg map
  • point-bastion-role
  • point-cd-runner-role
  • point-data-transfer-role
  • bastion-proxy-role
  • custodian-* roles
  • eks-worker-role, irsa roles…

Missing → locked out

Legacy point-stg EC2, still live, omitted from the map
  • ponta-proxy-role  (Squid)
  • point-hulft-role  (HULFT/NFS)
SSM agent needs group ssm (ssm+ssmmessages) + compute (ec2messages). Neither role had either.

06 The fix

Two lines. No reboot. Both boxes recover.

Add the missing roles to the stg role_endpoint_access map. Endpoint policies match aws:PrincipalArn at request time, so this only extends the allowlist — it does not require the roles to be Terraform-managed.

terraform/components/endpoints/tfvars/stg.tfvarsPR #135
  "point-data-transfer-role" = ["secrets", "storage", "compute", "ssm", "observability"]
+ "ponta-proxy-role" = ["secrets", "storage", "compute", "ssm", "observability"]
+ "point-hulft-role" = ["secrets", "storage", "compute", "ssm", "observability"]
Recovery. No reboot, no in-guest action. Once the policy allows the roles, each agent's next retry succeeds and both instances return to Online within minutes. Verify: aws ssm describe-instance-information --filters Key=InstanceIds,Values=i-042325ebdb8991aa9,i-0ce6fa785d00e57a0.

Note. A reboot or systemctl restart amazon-ssm-agent would not have fixed it — the agent comes back and hits the same endpoint-policy denial. prd hosts an equivalent hulft; if its endpoint policies apply from the same map they will need the same two roles.
