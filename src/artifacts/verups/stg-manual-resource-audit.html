Executive summary

point STG is a mature environment (41 Terraform state files since 2024-11), not an empty target. Of 1,190 live resources, the large majority are Terraform-managed, controller-managed (EKS/load-balancer-controller), or created by account-level automation (the ClassMethod “Members” MSP baseline and the Spring Boot app’s own SNS auto-provisioning). After re-validating every flagged candidate against the state index, 86 resources are genuinely manual — but the actionable signal is just 4 hard collisions + 2 apply dependencies that can block Phase 4.

Methodology & caveats

§2

State-membership is the only reliable signal

No default_tags / ManagedBy convention exists, so tags cannot prove Terraform ownership. A 1,006-identifier index (IDs + ARNs) was extracted from all 41 STG .tfstate files; each candidate was exact-tested for id / ARN / name membership.

“Manual” ≠ “human created in console”

MANUAL_LIKELY covers resources that simply are not state-tracked and predate the CloudTrail window. Only MANUAL_CONFIRMED has a captured human creation principal.

CloudTrail covers only ~90 days

Most manual resources here are older, so they show “no event in 90d window” rather than a creator. Where a human principal was captured (e.g. bk-20260430 snapshots via console + MFA) the item is confirmed.

Mature account, not empty target

“Phase 4 not started” = the migrated verup Terraform hasn’t been applied to STG yet; the account itself has run point Terraform since 2024-11. The risk is collision, not greenfield provisioning.

Spot-verified live (read-only): IAM role/user/policy existence, the three ACM cert IDs/types/statuses (which corrected fabricated cert IDs in the edge enumerator), and the planned infra/iam / s3-year-report names on branch release/verup. The IAM collision scan covered all release/verup components — only the three custodian-* roles collide.

Open questions for the engineer

  1. Ownership of the custodian-* IAM roles — should infra/iam adopt (import) the live roles, or replace them? Their live trust policies (Cloudflare IPs, bs-custodian, user/cicd, the temporary Dalian IP) must be reconciled before apply to avoid dropping access or locking out admins. The single most likely Phase-4 hard-fail.

  5. redirect-bse Lambda@Edge — who owns this manual us-east-1 function and its versioning? frontend-customer pins :17; a bump or deletion breaks the CloudFront association at apply.
