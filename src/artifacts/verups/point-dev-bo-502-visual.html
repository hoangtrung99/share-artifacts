Root cause · confirmed & reproduced

Point DEV Backoffice returns 502 on /admin/*

The admin API dies at the CloudFront → ALB origin TLS handshake: the load balancer's certificate *.backseat-service.com is a single-label wildcard that does not cover the two-label host bo.dev.backseat-service.com that CloudFront sends. The request never reaches the ALB — CloudFront generates the 502 itself.

env: point-dev · 905418018638 region: ap-northeast-1 dist: E3ETPFX8HYQZPU alb: point-alb
The one-sentence verdict

HTTPS from CloudFront to the ALB fails certificate validation for host bo.dev.backseat-service.com → 502. The BO page still loads because it is served from S3; only /admin/* is routed to the ALB.

02 · The rule that breaks it

A single-label wildcard matches exactly one label

Hyphens live inside a label; dots separate labels. Per RFC 6125 & AWS ACM, *.backseat-service.com matches one left label only.

Honest reading of OriginCommError

AWS defines it as an origin communication failure (connect/read), not a literal "certificate error". It pins the fault to the CloudFront→origin leg. The certificate is the proven mechanism via the wildcard rule (§02), the working single-label sibling (§05), the independent curl hostname rejection, and the sub-second time-taken that rules out a slow timeout.

07 · Fix

Two equivalent solutions — pick one

Both keep the HTTPS origin. The difference is: change the host, or add a certificate.

Solution 1 · cheapest

Rename to a single label: bo-dev.backseat-service.com

Hyphen instead of dot makes it one label, so the existing *.backseat-service.com covers it — no new certificate, on both viewer and origin legs.

Change: frontend-admin/tfvars/dev.tfvars → route53_record = "bo-dev.backseat-service.com" + route53_domain = "backseat-service.com". CloudFront alias follows automatically; ALB Ingress unchanged.

pro only 1 in-repo reference; app uses relative /admin/v1/* paths.  con the URL changes — update bookmarks / OAuth redirects / CORS.

Solution 2 · keep the URL

Add a cert covering bo.dev.backseat-service.com

Issue/import *.dev.backseat-service.com (also covers the sibling & future hosts) — the cert the disabled init/acm was designed to create.

Attach it to: the point-alb HTTPS:443 listener SNI list via point-ingress (stops the 502), and the CloudFront viewer cert in us-east-1 (removes the browser cert warning).

pro URL unchanged; matches the intended bo.dev.* design.  con needs a new DNS-validated cert in two regions.

Not recommended — revert origin to HTTP

Reverting to http-only also removes the 502 (no origin cert validation) but drops CloudFront↔ALB encryption — contrary to commit 18e2f4e5. And regardless of the chosen fix: set point-admin to replicas ≥ 2 + a PodDisruptionBudget.
