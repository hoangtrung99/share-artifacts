Mutagen: cách viết file config

Mọi thứ trong bài này đã đối chiếu với binary mutagen 0.18.1 đang chạy, không chỉ với tài liệu. Chỗ nào docs và binary lệch nhau đều được ghi rõ. Trang này giải thích cách viết config; còn cách vận hành hằng ngày nằm ở runbook sync hai máy.

Mô hình tư duy

Một session nối hai điểm cuối: alpha và beta. Tên gọi này quan trọng — mọi chế độ một chiều đều chảy từ alpha sang beta, và khi conflict thì alpha là bên "thắng" trong two-way-resolved.

Bên trong, Mutagen dùng three-way merge: nó nhớ trạng thái mà hai bên đã từng đồng thuận lần cuối, rồi so với hiện tại của từng bên để biết ai đã đổi cái gì. Nhờ vậy nó phân biệt được "A tạo file mới" với "B đã xoá file đó" — thứ mà rsync không làm được.

Mỗi chu kỳ gồm 4 bước, lặp lại mỗi khi filesystem đổi:

  1. scan — quét cây thư mục hai bên
  2. reconcile — so với trạng thái đồng thuận cũ, tính ra việc cần làm và các conflict
  3. stage — chuyển nội dung mới sang bên đích, ghi vào vùng tạm
  4. apply — chuyển vùng tạm vào đúng vị trí

Vì có bước stage riêng, một lần sync bị đứt giữa chừng sẽ không để lại file vỡ dở: nội dung chỉ được đặt vào vị trí thật khi đã nằm đủ trong vùng tạm. Vùng tạm mặc định ở ~/.mutagen/staging.

Ba tầng config, tầng dưới đè tầng trên

tầng 1 — yếu nhất

~/.mutagen.yml

Mặc định toàn cục cho mọi session mới. Chỉ có khối defaults, không đặt tên session ở đây.

tầng 2

mutagen.yml (project)

Khối defaults + các session có tên. Đây là nơi khai báo thật.

tầng 3 — mạnh nhất

flag lúc create

-m, --symlink-mode, -i… Đè lên mọi thứ.

Trong một project file, khối sync.defaults áp cho mọi session của project đó, và mỗi session có thể ghi đè từng key. Muốn bỏ qua hoàn toàn config toàn cục thì thêm --no-global-configuration.

Config bị "đóng băng" lúc tạo session. Sửa file rồi thì session đang chạy không tự đọc lại — Mutagen không có lệnh reload. Muốn áp dụng thì phải terminate rồi start lại. Việc này rẻ: session mới scan hai bên, thấy đã bằng nhau, và không truyền lại byte nào.

Bộ khung một project file

sync:
  defaults:                       # áp cho mọi session bên dưới
    mode: "two-way-safe"
    symlink:
      mode: "posix-raw"
    ignore:
      vcs: true                   # bỏ qua .git/.svn/.hg…
      paths:
        - ".DS_Store"

  ten-session-tuy-y:              # key chính là TÊN session
    alpha: "/duong/dan/local"
    beta:  "mini:/duong/dan/remote"
    mode: "one-way-replica"       # ghi đè defaults
    ignore:
      paths:
        - "node_modules/"
    configurationAlpha:           # chỉ áp cho alpha
      watch:
        mode: "no-watch"
    configurationBeta:            # chỉ áp cho beta
      permissions:
        defaultFileMode: 0644

forward:                          # tuỳ chọn: forward TCP/socket
  defaults: {}
  ten-forward:
    source: "tcp:localhost:5432"
    destination: "mini:tcp:localhost:5432"

beta dùng dạng <ssh-target>:<path>. Nếu mini là alias trong ~/.ssh/config thì Mutagen dùng đúng alias đó — nó gọi OpenSSH thật, nên mọi tuỳ chọn của anh trong ssh config đều có hiệu lực.

Root không được là symlink. Docs nói rõ: symlink có thể nằm trong cây sync hoặc trên đường dẫn cha, nhưng bản thân alpha/beta trỏ thẳng vào một symlink thì Mutagen từ chối. Nếu gặp, thay symlink đó bằng thư mục thật.

Chọn mode — quyết định quan trọng nhất

ModeChiềuKhi cùng một file đổi ở cả hai bênDùng khi
two-way-safe
mặc định		 Hai chiều Dừng session và báo conflict. Không tự chọn bên thắng, không mất dữ liệu. Cả hai máy đều là nơi sáng tác. Đặc biệt khi thư mục không nằm trong git — mất file là mất hẳn.
two-way-resolved Hai chiều alpha luôn thắng, bản của beta bị ghi đè im lặng. Khi anh chắc chắn một bên là chuẩn, nhưng vẫn muốn file mới ở beta đi ngược về.
one-way-safe alpha → beta Đẩy thay đổi từ alpha, nhưng không xoá thứ beta tự có. Deploy asset sang máy đích mà không muốn dọn sạch nó.
one-way-replica alpha → beta Beta thành bản sao chính xác của alpha. Mọi thứ beta tự tạo hoặc tự sửa đều bị xoá. Máy đích là gương thuần tuý. Một nguồn sự thật duy nhất.

Cách gỡ conflict: ở các mode *-safe, xoá nội dung ở phía anh muốn cho thua. Mutagen coi việc xoá là hợp lệ để ghi đè, nên chu kỳ kế tiếp sẽ đồng bộ lại theo phía còn lại. Nếu lịch sử session rối hẳn, mutagen sync reset <name> xoá trạng thái đồng thuận và bắt đầu lại từ đầu.

Ignore

Cú pháp gần như y hệt .gitignore. Đường dẫn tính tương đối từ gốc session, luôn dùng /.

MẫuNghĩa
node_modulesTên trơ (không có /) → khớp ở mọi cấp thư mục.
/buildCó / ở đầu → chỉ khớp ngay tại gốc session.
reports/Có / ở cuối → chỉ khớp thư mục, không khớp file.
*.tar.gzWildcard bình thường.
"!hotel"Phủ định. ["hot*", "!hotel"] = bỏ qua mọi thứ bắt đầu bằng "hot", trừ "hotel".
vcs: trueBỏ qua thư mục của mọi VCS (.git, .svn, .hg…). Tương đương flag --ignore-vcs.

Đừng bao giờ sync một thư mục chứa .git đang sống. File-sync một repo đang hoạt động sẽ phá nó: .git/index cache dữ liệu stat riêng của từng máy; ref bị lùi ngược theo kiểu last-writer-wins; một index.lock cũ sẽ khoá cứng máy bên kia; và git gc ở một bên xoá mất object mà ref bên kia còn trỏ tới. Dùng git remote. Nếu buộc phải sync cây có repo, bật ignore.vcs: true.

Symlink

ModeHành vi
portable
mặc định		Chỉ chấp nhận symlink tương đối và nằm trong cây sync. Gặp symlink tuyệt đối hoặc trỏ ra ngoài root → DỪNG session cho tới khi anh sửa.
posix-rawCopy nguyên văn target, không phân tích gì. Chỉ dùng được giữa hai hệ POSIX.
ignoreBỏ qua symlink hoàn toàn.

Cây ~/.claude/skills có 38 symlink tuyệt đối cộng một cái trỏ hẳn ra ngoài root (~/.agents/skills/superpowers → ~/.codex/superpowers/skills). Với mode mặc định portable, session sẽ halt ngay từ lần scan đầu. Vì thế posix-raw ở đây là bắt buộc, không phải sở thích.

Và cái bẫy đắt hơn: posix-raw copy symlink nguyên văn — nếu target của nó nằm ngoài cây sync và anh không sync target đó, link sẽ dangling ở máy đích, im lặng, không một dòng lỗi. Byte khớp hoàn hảo, mà skill thì biến mất.

Vòng đời session

# project (thao tác cả nhóm, đọc từ ./mutagen.yml hoặc -f <file>)
mutagen project start [-p] [-f file]   # -p = tạo sẵn ở trạng thái paused
mutagen project list|pause|resume|flush|terminate [-f file]

# session lẻ
mutagen sync create -n <ten> -m <mode> <alpha> <beta>
mutagen sync list [<ten>]              # trạng thái + số file hai bên
mutagen sync monitor <ten>             # theo dõi trực tiếp
mutagen sync flush <ten>               # CHẶN tới khi hai bên khớp
mutagen sync pause|resume <ten>
mutagen sync reset <ten>               # xoá lịch sử đồng thuận, bắt đầu lại
mutagen sync terminate <ten>           # xoá session (file vẫn còn nguyên)

# daemon
mutagen daemon start|stop|register|unregister

flush chặn tới khi chu kỳ xong, còn resume trả về ngay. Nên flush mới là câu trả lời trung thực cho "hai máy đã khớp chưa". Và flush một session đang paused sẽ báo lỗi — phải resume trước.

Những chỗ dễ vấp — đã gặp thật

  • Không có reload. Session đang sống là protobuf nhị phân trong daemon; sửa YAML không có tác dụng cho tới khi terminate + start.
  • project start mặc định chạy ngay. Nếu unit đang cố ý tắt, phải thêm -p, không thì việc sửa config sẽ âm thầm bật sync trở lại.
  • File .lock mới là thứ neo session. Mutagen sinh <file>.mutagen.yml.lock chứa project identifier. Di chuyển project file mà bỏ lock lại thì mất quyền điều khiển các session đang chạy, và lệnh start kế tiếp sẽ tạo bản trùng.
  • Config đóng băng lúc tạo. Kể cả ~/.mutagen.yml — sửa mặc định toàn cục không ảnh hưởng session đã tồn tại.
  • Daemon tự khởi động lại. Bất kỳ lệnh mutagen nào cũng auto-start daemon. Muốn daemon register/unregister chạy được thì phải stop và chờ tiến trình chết hẳn, hoặc đặt MUTAGEN_DISABLE_AUTOSTART=1.
  • Tên session nằm trong một namespace phẳng duy nhất của daemon, kể cả khi thuộc các project file khác nhau. Đặt tiền tố theo unit thì không đụng nhau.

Một config thật, giải thích từng dòng

sync:
  defaults:
    symlink:
      mode: "posix-raw"        # BẮT BUỘC: cây skills có 38 symlink tuyệt đối
                               # + 1 cái trỏ ra ngoài root -> `portable` sẽ HALT
    ignore:
      paths:
        - ".DS_Store"

  agents:                      # tên session (namespace phẳng -> đặt tiền tố theo unit)
    alpha: "/Users/hoangtrung/.agents"
    beta:  "mini:/Users/hoangtrung/.agents"
    mode: "one-way-replica"    # máy đích là GƯƠNG. Sửa skill ở đó = mất.
                               # Đó là chủ đích: một nguồn sự thật duy nhất.

  claude-sessions:
    alpha: "/Users/hoangtrung/.claude/projects"
    beta:  "mini:/Users/hoangtrung/.claude/projects"
    mode: "two-way-safe"       # transcript đặt tên theo UUID -> hai máy không bao giờ
                               # trùng tên file -> hợp nhất tự nhiên, không conflict
    ignore:
      paths:
        - "sessions-index.json"  # file tên CỐ ĐỊNH duy nhất trong cây -> SẼ đụng độ

  # history.jsonl cố ý VẮNG MẶT: hai máy cùng append vào một tên file,
  # và không công cụ nào merge được. Unison báo conflict rồi bỏ qua,
  # Mutagen dừng session, Syncthing đẻ file conflict, rsync ghi đè im lặng.
