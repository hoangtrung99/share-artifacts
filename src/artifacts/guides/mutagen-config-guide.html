Tham chiếu · Mutagen 0.18.1

Mutagen: cách viết file config

Mọi giá trị mặc định trong trang này lấy trực tiếp từ mutagen sync list --long của binary đang chạy, không phải chép từ tài liệu. Chỗ nào docs và binary lệch nhau đều được ghi rõ. Vận hành hằng ngày: runbook sync hai máy.

mini: trong beta là gì?

beta: "mini:/Users/hoangtrung/Work/solashi/verup/docs"

mini không phải khái niệm của Mutagen. Nó là một SSH alias, định nghĩa trong ~/.ssh/config. Mutagen không tự cài đặt SSH — nó gọi OpenSSH thật, nên bất cứ thứ gì ssh mini hiểu được thì Mutagen cũng hiểu. 

# ~/.ssh/config
Host mini
  HostName hongs-mac-mini.tail7d178b.ts.net   # Tailscale FQDN — định danh cố định
  User hoangtrung
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  IdentityAgent none                          # chặn agent của password manager
  ServerAliveInterval 10

Ba cách viết dưới đây cho kết quả hệt nhau:

beta: "mini:/Users/hoangtrung/.../docs"                                        # alias
beta: "hoangtrung@hongs-mac-mini.tail7d178b.ts.net:/Users/hoangtrung/.../docs" # đầy đủ
beta: "hoangtrung@100.68.178.93:/Users/hoangtrung/.../docs"                    # IP

Ngữ pháp URL của Mutagen

DạngNghĩa
/duong/danKhông có : → đường dẫn local.
<ssh-target>:/duong/danCó : → endpoint qua SSH. ssh-target là bất cứ thứ gì OpenSSH nhận: alias, user@host, IP.
docker://<container>/duong/danEndpoint bên trong một Docker container.

Vì sao nên dùng alias thay vì host đầy đủ: đổi máy đích, đổi mạng, đổi key — chỉ sửa một chỗ trong ~/.ssh/config, file Mutagen không đổi một ký tự. Đây là tách bạch trách nhiệm thật sự: file Mutagen nói cái gì được sync; file SSH nói tới đâu và bằng cách nào.

Hệ quả ngược: mọi bug SSH đều trở thành bug Mutagen. Nếu khối Host mini nằm dưới một khối Host * có IdentityAgent trỏ vào password-manager, agent đó sẽ chào quá nhiều key và chạm MaxAuthTries của máy đích. Triệu chứng hiện ra là session kẹt ở Connecting to beta — trông như lỗi Mutagen, thực chất là lỗi SSH config.

Mô hình tư duy

Một session nối hai endpoint: alpha và beta. Tên gọi này có sức nặng — mọi chế độ một chiều đều chảy từ alpha sang beta, và trong two-way-resolved thì alpha là bên thắng khi conflict.

Bên trong, Mutagen dùng three-way merge: nó lưu trạng thái mà hai bên đã từng đồng thuận lần cuối, rồi so với hiện tại của từng bên. Nhờ vậy nó phân biệt được "A tạo file mới" với "B đã xoá file đó" — thứ mà rsync không bao giờ phân biệt nổi, vì rsync chỉ nhìn thấy "bên này có, bên kia không".

Mỗi chu kỳ gồm 4 bước, chạy lại mỗi khi filesystem đổi:

  1. scan — quét cây thư mục hai bên
  2. reconcile — so với trạng thái đồng thuận cũ, tính ra việc cần làm và các conflict
  3. stage — chuyển nội dung mới sang bên đích, ghi vào vùng tạm
  4. apply — đưa từ vùng tạm vào đúng vị trí

Nhờ có bước stage riêng, sync đứt giữa chừng không để lại file vỡ dở: nội dung chỉ vào vị trí thật khi đã nằm đủ trong vùng tạm (mặc định ~/.mutagen/staging).

Bốn file config — ai đọc file nào

FileAi đọcTrả lời câu hỏi
~/.ssh/configOpenSSH"mini" là máy nào, dùng key gì
~/.mutagen.ymlMutagenMặc định toàn cục cho mọi session mới (ở setup này: cố ý không tạo)
<unit>.mutagen.ymlMutagenSession nào, mode gì, ignore gì
<unit>.rsync.confmsyncĐường dẫn nào seed bulk bằng rsync

Hai file cuối là hai tầng khác nhau, không thay thế nhau: rsync làm bản copy đầu tiên (bulk, một chiều), Mutagen giữ tươi sau đó. Mutagen không có cơ chế bulk-seed — để nó tự tải 20 GB qua chu kỳ sync thường thì chậm và phình vùng staging.

Ba tầng config, tầng dưới đè tầng trên

tầng 1 — yếu nhất

~/.mutagen.yml

Chỉ có khối sync.defaults. Không đặt tên session ở đây được.

tầng 2

project file

sync.defaults + các session có tên. Nơi khai báo thật.

tầng 3 — mạnh nhất

flag lúc create

-m, --symlink-mode, -i… Đè lên tất cả.

Bỏ qua hoàn toàn tầng 1: thêm --no-global-configuration. Nạp thêm file config phụ: -c <file> (có thể lặp nhiều lần, chúng được merge).

Config bị đóng băng lúc tạo session. Sửa file rồi thì session đang chạy không đọc lại — Mutagen không có lệnh reload. Kể cả sửa ~/.mutagen.yml cũng không ảnh hưởng session đã tồn tại. Muốn áp dụng: terminate rồi start lại. Việc này rẻ — session mới scan hai bên, thấy đã bằng nhau, và không truyền lại byte nào.

Ignore của session được CỘNG THÊM vào defaults, không phải ghi đè. Nếu defaults đã có .DS_Store mà session khai lại, nó sẽ xuất hiện hai lần trong danh sách hiệu lực — xem được bằng mutagen sync list --long.

Bộ khung một project file

beforeCreate:                     # hook: chạy trong shell TRƯỚC khi tạo session
  - echo "starting"
afterTerminate:                   # hook: chạy SAU khi xoá toàn bộ session
  - echo "stopped"

sync:
  defaults:                       # áp cho MỌI session bên dưới
    mode: "two-way-safe"
    symlink:
      mode: "posix-raw"
    ignore:
      vcs: true
      paths:
        - ".DS_Store"

  ten-session:                    # key CHÍNH LÀ tên session
    alpha: "/duong/dan/local"
    beta:  "mini:/duong/dan/remote"
    mode: "one-way-replica"       # ghi đè defaults
    flushOnCreate: true           # ép 1 chu kỳ đầy đủ ngay sau khi tạo
    ignore:
      paths:
        - "node_modules/"         # CỘNG vào ignore của defaults
    configurationAlpha:           # chỉ áp cho ĐẦU alpha
      watch:
        mode: "no-watch"
    configurationBeta:            # chỉ áp cho ĐẦU beta
      permissions:
        defaultFileMode: 0644

forward:                          # tuỳ chọn: forward TCP/unix socket
  ten-forward:
    source: "tcp:localhost:5432"
    destination: "mini:tcp:localhost:5432"

Hook có 4 cặp: beforeCreate/afterCreate, beforePause/afterPause, beforeResume/afterResume, beforeTerminate/afterTerminate. Chúng chạy cho cả project, không phải từng session.

Root không được là symlink. Symlink có thể nằm bên trong cây sync hoặc trên đường dẫn cha, nhưng alpha/beta trỏ thẳng vào một symlink thì Mutagen từ chối. Gặp thì thay bằng thư mục thật.

Giải thích từng key

mode

mặc định: two-way-safe two-way-safe two-way-resolved one-way-safe one-way-replica

Key quan trọng nhất. Nó quyết định chuyện gì xảy ra khi hai bên cùng đổi một file — và đó là lúc dữ liệu bị mất hoặc được cứu.

ModeChiềuKhi cùng file đổi ở cả hai bênChọn khi
two-way-safeHai chiều DỪNG session, báo conflict, chờ người. Không tự chọn bên thắng. Cả hai máy đều là nơi sáng tác. Đặc biệt khi thư mục không nằm trong git — mất file là mất hẳn.
two-way-resolvedHai chiều alpha luôn thắng; bản của beta bị ghi đè im lặng. Một bên chắc chắn là chuẩn, nhưng vẫn muốn file mới ở beta đi ngược về.
one-way-safealpha → beta Đẩy thay đổi từ alpha, nhưng không xoá thứ beta tự có. Deploy asset sang máy đích mà không muốn dọn sạch nó.
one-way-replicaalpha → beta Beta thành bản sao chính xác. Mọi thứ beta tự tạo/sửa đều bị xoá. Máy đích là gương thuần tuý. Một nguồn sự thật duy nhất.

Cách gỡ conflict ở mode *-safe: xoá nội dung ở phía anh muốn cho thua. Mutagen coi việc xoá là hợp lệ để bị ghi đè, nên chu kỳ kế tiếp sẽ đồng bộ theo phía còn lại. Nếu lịch sử rối hẳn: mutagen sync reset <name> — xoá trạng thái đồng thuận, bắt đầu lại từ đầu.

symlink.mode

mặc định: portable portable posix-raw ignore
portableChỉ chấp nhận symlink tương đối và nằm trong cây sync. Gặp symlink tuyệt đối hoặc trỏ ra ngoài root → DỪNG session cho tới khi anh sửa.
posix-rawCopy nguyên văn target, không phân tích. Chỉ dùng được giữa hai hệ POSIX.
ignoreBỏ qua symlink hoàn toàn.

Cây ~/.claude/skills có 38 symlink tuyệt đối, cộng một cái trỏ hẳn ra ngoài root (~/.agents/skills/superpowers → ~/.codex/superpowers/skills). Với portable, session halt ngay lần scan đầu. Nên posix-raw ở đây là bắt buộc, không phải sở thích.

Bẫy đắt hơn: posix-raw copy link nguyên văn. Nếu target nằm ngoài cây sync và anh không sync target đó, link sẽ dangling ở máy đích, im lặng, không một dòng lỗi. Byte khớp hoàn hảo — mà skill thì biến mất.

ignore.paths / ignore.vcs

ignore.vcs mặc định: false (Propagate — .git ĐƯỢC sync)

Cú pháp gần như y hệt .gitignore. Đường dẫn tính tương đối từ gốc session, luôn dùng /.

MẫuNghĩa
node_modulesTên trơ (không có /) → khớp ở mọi cấp thư mục.
/build/ ở đầu → chỉ khớp ngay tại gốc session.
reports// ở cuối → chỉ khớp thư mục, không khớp file.
*.tar.gzWildcard.
"!hotel"Phủ định. ["hot*", "!hotel"] = bỏ qua mọi thứ bắt đầu bằng "hot", trừ "hotel".
vcs: trueBỏ qua thư mục VCS (.git, .svn, .hg…). Mặc định là false — tức là .git được sync nếu anh không nói gì.

Đừng sync một thư mục chứa .git đang sống. File-sync một repo đang hoạt động sẽ phá nó: .git/index cache dữ liệu stat riêng của từng máy; ref bị lùi ngược kiểu last-writer-wins; một index.lock cũ khoá cứng máy bên kia; git gc ở một bên xoá object mà ref bên kia còn trỏ tới. Dùng git remote. Nếu buộc phải sync cây có repo: bật ignore.vcs: true.

watch.mode / watch.pollingInterval

mặc định: portable, polling 10 giây portable force-poll no-watch
  • portable — dùng cơ chế native của OS nếu có (FSEvents trên macOS), fallback sang poll.
  • force-poll — luôn poll. Cần khi filesystem không hỗ trợ watch (một số network mount).
  • no-watch — tắt hẳn theo dõi. Session chỉ sync khi anh gọi flush tay.

no-watch là cách khai báo "unit này luôn thủ công" ngay ở tầng config, thay vì phải nhớ pause ở tầng lệnh. Nếu anh muốn một project chỉ sync khi gọi tay, đây là key đúng.

scanMode

mặc định: accelerated full accelerated

accelerated tận dụng kết quả từ watcher để chỉ scan lại phần đã đổi — nhanh hơn hẳn trên cây lớn. full quét lại toàn bộ mỗi chu kỳ; chỉ cần khi anh nghi watcher bỏ sót thay đổi.

stageMode

mặc định: mutagen (thư mục ~/.mutagen) mutagen neighboring

Vùng tạm nằm ở ~/.mutagen/staging, hay ngay cạnh thư mục đích. Dùng neighboring khi ~/.mutagen và thư mục đích nằm khác ổ đĩa — lúc đó bước apply là rename nguyên tử trong cùng filesystem, thay vì copy chéo ổ.

Docs lệch binary: tài liệu liệt kê thêm internal, nhưng mutagen 0.18.1 chỉ nhận mutagen|neighboring — theo chính mutagen sync create --help.

probeMode

mặc định: probe probe assume

Mutagen cần biết filesystem hỗ trợ gì (phân biệt hoa/thường, lưu được quyền thực thi không…). probe = thử nghiệm thật bằng cách ghi file tạm. assume = suy ra từ OS. Chỉ đổi khi probe gây vấn đề trên filesystem lạ.

maxEntryCount / maxStagingFileSize

mặc định: 2⁶⁴−1 entry · 18 EB — tức là KHÔNG giới hạn

Chốt an toàn, và mặc định là tắt. Session sẽ từ chối chạy nếu cây vượt số entry, hoặc nếu có file đơn lẻ vượt kích thước. Đây là thứ cứu anh khi lỡ tay trỏ alpha vào $HOME hay vào một thư mục có file dump 50 GB. 

maxEntryCount: 50000
maxStagingFileSize: "100 MB"

permissions.*

mặc định: file 0600 · thư mục 0700 · owner/group giữ nguyên

Quyền áp cho nội dung tạo mới ở đầu bên kia, khi filesystem không giữ được quyền gốc. Mặc định khá chặt (0600) — nếu máy đích cần file đọc được bởi user khác (web server, service account), đặt defaultFileMode: 0644 trong configurationBeta. 

configurationBeta:
  permissions:
    defaultFileMode: 0644
    defaultDirectoryMode: 0755

hash

mặc định: sha1 sha1 sha256 xxh128

Thuật toán băm để phát hiện nội dung đổi. xxh128 nhanh hơn đáng kể và không phải hàm mật mã — đúng cho sync (mục tiêu là phát hiện thay đổi, không phải chống giả mạo). Đổi hash buộc scan lại toàn bộ.

flushOnCreate

mặc định: false

Ép một chu kỳ đầy đủ ngay khi tạo session, và chờ nó xong trước khi hook afterCreate chạy. Hữu ích khi có thứ khác phụ thuộc vào dữ liệu đã sync xong (ví dụ hook khởi động container).

configurationAlpha / configurationBeta

Khối config con, chỉ áp cho một đầu. Dùng khi hai máy khác nhau về filesystem, quyền, hay khả năng watch — ví dụ máy đích là network mount thì đặt watch.mode: force-poll chỉ cho beta.

Mapping: mutagen thuần ↔ msync

msync không thay thế Mutagen — nó là wrapper mỏng, thêm đúng 3 thứ Mutagen không có: khái niệm unit, tầng rsync bulk-seed, và bảo toàn trạng thái on/off.

Việcmutagen thuầnmsync
Xem trạng tháimutagen sync listmsync status [unit]
Xem config hiệu lực (kèm mặc định)mutagen sync list --long <name>—
Tạo sessionmutagen project start -f <unit>.mutagen.ymlmsync apply <unit>
Áp dụng config đã sửamutagen project terminate -f X
mutagen project start -f X		msync apply <unit>
Tạm dừngmutagen project pause -f Xmsync off <unit>
Chạy lạimutagen project resume -f Xmsync on <unit>
Sync một lần rồi tắt lạiresume -f X → flush -f X → pause -f Xmsync now <unit>

Kiểm tra máy đích chạy được khôngMutagen không làmmsync audit

Ba giá trị msync thật sự thêm vào

  • msync now — Mutagen báo lỗi nếu flush một session đang paused. Phải resume → flush → pause. msync now gói đúng ba bước đó và khôi phục trạng thái cũ, nên sync thủ công bao nhiêu lần cũng được mà unit không bị bật lén.
  • msync apply — mutagen project start mặc định chạy ngay. Áp config cho unit đang tắt sẽ âm thầm bật nó lên. msync apply đọc trạng thái trước và thêm -p nếu cần.
  • msync seed — Mutagen không có bulk copy. Để nó tự tải 20 GB qua chu kỳ thường thì chậm và phình staging. rsync làm bước đó, Mutagen chỉ giữ tươi.

Nếu bỏ msync, gõ Mutagen thuần

cd ~/machine-sync/config/units

mutagen project start     -f verup.mutagen.yml   # dựng session (thêm -p để tạo sẵn ở trạng thái paused)
mutagen sync list                                 # xem
mutagen sync list --long verup-docs               # xem config hiệu lực + mặc định
mutagen project pause     -f verup.mutagen.yml    # tắt
mutagen project resume    -f verup.mutagen.yml    # bật
mutagen project flush     -f verup.mutagen.yml    # sync ngay, CHẶN tới khi xong
mutagen project terminate -f verup.mutagen.yml    # xoá session (file vẫn còn nguyên)

Hoàn toàn dùng được. msync chỉ tiết kiệm thao tác và chặn hai cái bẫy ở trên.

Vòng đời session — lệnh đầy đủ

# project — thao tác cả nhóm; đọc ./mutagen.yml, hoặc -f <file>
mutagen project start [-p] [-f file]
mutagen project list|pause|resume|flush|terminate [-f file]

# session lẻ
mutagen sync create -n <ten> -m <mode> [-i <ignore>] [--symlink-mode …] <alpha> <beta>
mutagen sync list [--long] [<ten>]     # --long in ra CONFIG HIỆU LỰC + mọi mặc định
mutagen sync monitor <ten>             # theo dõi trực tiếp
mutagen sync flush <ten>               # CHẶN tới khi hai bên khớp
mutagen sync pause|resume <ten>
mutagen sync reset <ten>               # xoá lịch sử đồng thuận, làm lại từ đầu
mutagen sync terminate <ten>

# daemon
mutagen daemon start|stop|register|unregister

flush chặn tới khi chu kỳ xong; resume trả về ngay lập tức. Nên chỉ flush mới trả lời trung thực câu "hai máy đã khớp chưa".

Những chỗ dễ vấp — đã gặp thật

  • Không có reload. Session đang sống là protobuf nhị phân trong daemon; sửa YAML vô tác dụng cho tới khi terminate + start.
  • project start mặc định chạy ngay. Unit đang cố ý tắt thì phải thêm -p, không thì sửa config sẽ âm thầm bật sync trở lại.
  • File .lock mới là thứ neo session. Mutagen sinh <file>.mutagen.yml.lock chứa project identifier, và gắn nó vào session dưới dạng label io.mutagen.project. Di chuyển project file mà bỏ lock lại → mất quyền điều khiển session đang chạy, và lệnh start kế tiếp tạo bản trùng.
  • Ignore của session CỘNG vào defaults. Khai lại cùng một mẫu ở cả hai nơi thì nó xuất hiện hai lần.
  • Daemon tự khởi động lại. Bất kỳ lệnh mutagen nào cũng auto-start daemon. Muốn daemon register/unregister chạy được thì phải stop và chờ tiến trình chết hẳn, hoặc đặt MUTAGEN_DISABLE_AUTOSTART=1.
  • Tên session nằm trong MỘT namespace phẳng của daemon, kể cả khi thuộc các project file khác nhau. Đặt tiền tố theo unit thì không đụng nhau.
  • Mặc định KHÔNG bỏ qua .git. ignore.vcs mặc định là false.
