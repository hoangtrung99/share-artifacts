Runbook · hai máy, một môi trường

MacBook Pro ⇄ Mac mini

Mac mini là bản sao đầy đủ của môi trường Claude + project verup trên MacBook. MacBook là nguồn sự thật. Nền tảng: một lần seed bằng rsync, sau đó Mutagen giữ đồng bộ liên tục qua Tailscale.

Dùng hằng ngày

msync status Daemon, autostart, và 11 session đang ở trạng thái nào. msync off Tắt sync nền. Session vẫn còn, chỉ ngừng truyền. Hai máy bắt đầu lệch nhau. msync on Bật lại sync nền. Thay đổi lan sang máy kia trong ~2 giây. msync now Sync một lần rồi trả về đúng trạng thái trước đó. Chạy được cả khi đang tắt. msync seed rsync toàn bộ: repo code + secrets + config. Thứ Mutagen không gánh. msync audit 34 phép kiểm tra hành vi trên mini. Chuẩn: 34 pass / 0 fail. msync autostart off Daemon thôi tự chạy khi đăng nhập.

Vì sao msync now cần tồn tại: Mutagen báo lỗi nếu flush một session đang pause. Nên lệnh này tự resume → flush → pause lại. Nó chỉ trả về khi hai máy thật sự đã khớp, khác với msync on (trả về ngay lập tức, sync diễn ra ở nền).

Ba trạng thái

ON

11 session Watching for changes. Sửa file bên nào cũng lan sang bên kia sau ~2 giây. Đây là mặc định.

OFF

11 session [Paused]. Không có gì truyền đi. Dùng khi cần refactor lớn, hoặc muốn thử nghiệm trên một máy mà không ảnh hưởng máy kia.

NOW

Không phải trạng thái — là một hành động. Đẩy toàn bộ thay đổi tồn đọng, chờ xong, rồi khôi phục ON/OFF như cũ.

Dựng lại từ số không

# 1. Kênh truyền: cài pubkey lên mini (chỉ lần đầu, cần mật khẩu mini)
ssh-copy-id -o PreferredAuthentications=password -o PubkeyAuthentication=no \
            -o IdentityAgent=none -i ~/.ssh/id_ed25519.pub hoangtrung@hongs-mac-mini.tail7d178b.ts.net

# 2. Seed toàn bộ bằng rsync (~20 GB, ~8 phút qua LAN)
cd ~/Work/solashi/verup/scripts/sync-machines
./sync-machines.sh preflight     # ssh, $HOME khớp, dung lượng, rsync, đường truyền
./sync-machines.sh all -n        # dry-run: in ra mọi file sẽ đụng tới
./sync-machines.sh all           # chạy thật
./sync-machines.sh postflight    # prune worktree cũ + in checklist re-auth

# 3. Sync liên tục
brew install mutagen-io/mutagen/mutagen
./mutagen-sessions.sh create     # dựng 11 session từ định nghĩa text
msync autostart on
msync audit                      # kỳ vọng: 34 pass / 0 fail

# 4. Trên mini, một lần: chạy `claude`, đăng nhập, auth MCP OAuth.
#    Không cơ chế file-sync nào làm thay được bước này.

Những cái bẫy đã thật sự cắn

Byte khớp không chứng minh gì

Ba lần liên tiếp, một file sang mini nguyên vẹn 100% — dung lượng khớp, checksum khớp — mà thứ cần nó vẫn hỏng, vì thứ nó trỏ tới nằm ngoài mọi sync root. Và cả ba đều hỏng im lặng.

Hỏng gìVì saoTriệu chứng
14 skill superpowers ~/.agents/skills/superpowers là symlink trỏ ra ~/.codex/superpowers/skills Skill biến mất. Không một dòng lỗi.
Mọi lần SSH login ~/.zshrc source vào ~/.zsh/, chưa từng được sync no such file or directory
MCP server ccc Cần ~/.cocoindex_code/global_settings.yml ở cấp HOME ccc: ✘ Failed to connect

Cách phòng duy nhất là kiểm tra hành vi, không kiểm tra byte. Đó là việc của msync audit: nó chạy zsh -il, claude mcp list, git status thật trên mini và đọc kết quả, thay vì so du.

Cáp USB-C là đường chậm nhất

Đo thật: cáp enumerate thành 100baseTX ≈ 11 MB/s. LAN đo được ≈ 50 MB/s. Cáp chỉ nhanh hơn nếu là Thunderbolt/USB4 thật. Tệ hơn: mDNS hoangs-mac-mini.local trả về cả địa chỉ link-local của cáp lẫn địa chỉ LAN, và ssh chọn ngẫu nhiên — cùng một lệnh sync có lúc chạy chậm gấp 4,5 lần mà không rõ vì sao. Vì thế mọi thứ đều bám Tailscale FQDN: định danh cố định, tự đi direct qua LAN khi cùng mạng, và vẫn chạy khi mang MacBook ra khỏi nhà.

Alias mini phải nằm trên cùng ~/.ssh/config

ssh lấy giá trị đầu tiên nó thấy cho mỗi keyword. Một khối Host * nằm dưới đang ép IdentityAgent sang 1Password agent, agent này chào đủ nhiều key để chạm MaxAuthTries của mini trước khi tới được lượt auth hợp lệ. Triệu chứng: Too many authentication failures.

Sửa skill trên mini sẽ mất

Tầng config là one-way-replica — đó chính là ý nghĩa của nó. Mini là gương. Muốn sửa skill thì sửa trên MacBook. Ngược lại, docs/ và transcript session là hai chiều, viết ở đâu cũng an toàn.
