Tùy Chọn Cloudflare WARP Không Cần Admin

routing có chọn lọc cho macOS — 4 cách tiếp cận

Tình huống: bạn bắt buộc dùng Cloudflare WARP của công ty để truy cập dịch vụ (AWS, private apps), nhưng không muốn WARP ảnh hưởng toàn bộ mạng máy. Bạn không có quyền admin trên Zero Trust dashboard, và dịch vụ là public service (như AWS) — chỉ cần egress IP đúng + posture "WARP connected".

Tài liệu này trình bày 4 cách để giải quyết, từ tối ưu nhất đến fallback.

Chọn cách nào?
Có Android?
Có — chọn Cách A (Android SSH Proxy). Đơn giản, ổn định, dùng host browser.
Có + muốn kết nối qua tailnet — chọn Cách B (Android Tailscale Proxy). Phức tạp hơn nhưng kết nối mọi nơi, không cần cùng WiFi/USB.
Không?
Chọn Cách C (VM Isolation — UTM). Cài WARP trong VM, host sạch hoàn toàn.
Cần nhanh?
Chọn Cách D (Toggle On/Off). Bật WARP khi cần, tắt khi xong. Không tối ưu nhưng không cần setup.
Ràng buộc đã xác nhận:
  • Dịch vụ: public service (AWS) — chỉ cần egress IP + posture "WARP connected"
  • Không cần host-specific posture signals (disk encryption, EDR, managed cert)
  • Không có quyền admin Zero Trust dashboard
  • Bắt buộc dùng Cloudflare công ty
Cả 4 cách thỏa mãn
Cách A — Android SSH Proxy

Android chạy Cloudflare WARP (VpnService — capture toàn bộ outbound traffic) + SimpleSSHD (SSH server port 2222). Mac kết nối qua SSH dynamic forwarding (ssh -D) tạo SOCKS5 proxy local. Chỉ app nào trỏ vào proxy mới đi qua WARP.

Root không cần thiết. SimpleSSHD chạy trên port 2222 (unprivileged).

Trỏ app vào proxy

Cách B — Android Tailscale Proxy

Giống Cách A, nhưng Mac kết nối đến Android qua Tailscale tailnet thay vì WiFi/USB. Lợi ích: kết nối mọi nơi, không cần cùng mạng, encrypted mesh.

Thách thức: Android chỉ cho phép một VpnService cùng lúc. Tailscale app tiêu chuẩn và WARP đều dùng VpnService — xung đột. Giải pháp: chạy tailscaled ở chế độ userspace networking (không dùng VpnService).

Conflict xác nhận: Tailscale app tiêu chuẩn + WARP = không thể chạy cùng lúc trên Android. Cả hai đều dùng VpnService. Android chỉ cho phép 1 VpnService active.

Mac — kết nối qua tailnet

SSH tunnel qua tailnet IP

Cài Tailscale trên Mac, join cùng tailnet. SSH đến Android qua tailnet IP thay vì local IP.

# SSH tunnel qua tailnet (thay blackshark.internal bằng tailnet IP) ssh -D 1080 -N -p 8022 <android-tailnet-ip> # Hoặc thêm vào ~/.ssh/config Host blackshark-tailnet HostName 100.x.x.x # tailnet IP của Android Port 8022 User root DynamicForward 1080 ServerAliveInterval 60

Sau đó dùng bse-on bình thường — PAC + CLI + forward đều hoạt động qua tailnet.

Cách B vs Cách A: Tailscale thêm latency (mesh relay) nhưng giải phóng khỏi WiFi/USB. Nếu Mac và Android luôn cùng WiFi/USB — Cách A đơn giản hơn. Nếu cần kết nối từ xa (khác mạng) — Cách B là lựa chọn duy nhất.

Cách D — Toggle On/Off (Fallback)

Không setup phức tạp. Bật WARP khi cần AWS, tắt khi xong. Giảm blast radius theo thời gian — WARP chỉ ảnh hưởng toàn mạng khi bạn đang cần AWS.

# Bật WARP khi cần AWS warp-cli connect # Tắt WARP khi xong warp-cli disconnect # Kiểm tra trạng thái warp-cli status

Aliases cho nhanh (thêm vào ~/.zshrc hoặc ~/.bashrc):

# Alias nhanh alias bse-on='warp-cli connect' alias bse-off='warp-cli disconnect' alias bse-status='warp-cli status'
Hạn chế: Khi WARP on, toàn bộ traffic máy đi qua WARP — không chỉ AWS. Nếu session AWS cần WARP liên tục (egress IP allowlist), bạn phải giữ WARP on suốt phiên.

Lưu ý quan trọng
1. DNS Leak — LUÔN dùng socks5h://
Dùng socks5h:// (remote DNS resolution) thay vì socks5:// (local DNS). Remote DNS đảm bảo: (a) DNS queries đi qua WARP, (b) Access policies match đúng, (c) không leak DNS ra ngoài.
2. Posture Check — chỉ hoạt động nếu
Công ty chỉ require "WARP connected" posture hoặc egress IP allowlist. Không hoạt động nếu posture check yêu cầu host-specific signals (disk encryption, EDR agent, managed-device cert) — Android/VM sẽ fail posture và bị block Access.
3. Performance — chấp nhận được cho console/API
WiFi/USB latency + WARP tunnel overhead. Phù hợp cho AWS console, API calls. Có thể chậm cho download lớn hoặc streaming.
4. SSH Timeout — thêm keepalive
Thêm ServerAliveInterval 60 vào SSH config để tránh timeout khi idle.
Checklist verify
  • WARP connected trên Android/VM — app hiện "Connected"
  • SSH tunnel established — không lỗi, ssh -D 1080 -N -p 2222 ... chạy không error
  • curl --socks5-hostname 127.0.0.1:1080 https://www.cloudflare.com/cdn-cgi/trace hiện warp=on
  • curl https://www.cloudflare.com/cdn-cgi/trace (direct, không proxy) hiện warp=off
  • Browser qua proxy vào được AWS
  • Browser không qua proxy không đi qua WARP (kiểm tra IP tại ipleak.net)
  • DNS resolve qua proxy — dùng socks5h://, verify DNS server tại dnsleaktest.com

#!/bin/bash
# BSE Proxy Toggle — selective WARP routing via PAC
# Default: bse-on = PAC mode (selective)
# Fallback: bse-socks = SOCKS mode (all traffic)

BSE_SSH_HOST="blackshark"
BSE_PROXY_PORT=1080
BSE_PAC_FILE="$HOME/.proxy/aws-proxy.pac"
BSE_IP_LIST="$HOME/.proxy/bse-ip-list.conf"
BSE_FORWARD_CONF="$HOME/.proxy/bse-forward.conf"
BSE_PAC_PORT=8799
BSE_PAC_URL="http://127.0.0.1:${BSE_PAC_PORT}/aws-proxy.pac"

# Detect active network service from default route
_bse_net_service() {
  local intf svc
  intf=$(route -n get default 2>/dev/null | awk '/interface:/{print $2}')
  if [ -n "$intf" ]; then
    svc=$(networksetup -listnetworkserviceorder 2>/dev/null | \
      grep "Device: ${intf})" -B1 | head -1 | sed 's/(.*) //')
  fi
  [ -z "$svc" ] && svc="Wi-Fi"
  echo "$svc"
}

# SSH tunnel
bse-connect() {
  lsof -i :${BSE_PROXY_PORT} -sTCP:LISTEN >/dev/null 2>&1 && return 0
  ssh -fN "${BSE_SSH_HOST}"
}
bse-disconnect() { pkill -f "ssh.*-fN.*${BSE_SSH_HOST}"; }

# PAC generation from IP config
bse-gen-pac() {
  # Reads bse-ip-list.conf → generates PAC with shExpMatch + isInNet
  # AWS domains hardcoded; backseat IPs from config
  # Output: ~/.proxy/aws-proxy.pac
  ...
}

# PAC HTTP server (macOS browsers don't load file:// PAC)
bse-pac-serve() {
  python3 -c "
    import http.server, socketserver
    class H(http.server.SimpleHTTPRequestHandler):
        def end_headers(self):
            if self.path.endswith('.pac'):
                self.send_header('Content-Type', 'application/x-ns-proxy-autoconfig')
            super().end_headers()
    socketserver.TCPServer(('127.0.0.1', 8799), H).serve_forever()
  " &
}

# PAC mode (default)
bse-pac-on() {
  bse-gen-pac; bse-pac-serve
  networksetup -setautoproxyurl "$net" "$BSE_PAC_URL"
  networksetup -setautoproxystate "$net" on
}

# SOCKS mode (fallback)
bse-proxy-on() {
  networksetup -setsocksfirewallproxy "$net" 127.0.0.1 1080
  networksetup -setsocksfirewallproxystate "$net" on
}

# CLI env vars (PAC doesn't affect CLI)
bse-cli-on() {
  export HTTPS_PROXY=socks5h://127.0.0.1:1080
  export ALL_PROXY=socks5h://127.0.0.1:1080
}

# TCP port forward (RDP/SSH/MySQL — non-HTTP, PAC không cover)
_bse_do_forward() {
  ssh -fN -L ${lport}:${ip}:${rport} ${BSE_SSH_HOST}
}
bse-forward() {
  # --rdp / --ssh / --mysql / --all → read from bse-forward.conf
  #   [local] → custom forward
  case "$1" in
    --all)  while read config; do _bse_do_forward ...; done ;;
    --*)    _bse_forward_by_name "${1#--}" ;;
    *)      _bse_do_forward "$1" "$2" "$3" ;;
  esac
}
bse-forward-list()   { ... }  # lsof ports ≥10000
bse-forward-kill()   { ... }  # kill 1 port
bse-forward-killall() { ... } # kill all ports ≥10000

# All-in-one
bse-on() {
  bse-connect; bse-pac-on; bse-cli-on
  # Parse flags: --forward-rdp --forward-ssh --forward-mysql --forward-all
  for arg in "$@"; do
    case "$arg" in
      --forward-rdp)   bse-forward --rdp ;;
      --forward-ssh)   bse-forward --ssh ;;
      --forward-mysql) bse-forward --mysql ;;
      --forward-all)   bse-forward --all ;;
    esac
  done
  bse-status
}
bse-socks() { bse-connect; bse-proxy-on; bse-cli-on; bse-status; }
bse-off()   { bse-cli-off; bse-forward-killall; bse-pac-off; bse-proxy-off; bse-disconnect; }

bse-status() { ... }  # network + tunnel + PAC + SOCKS + CLI + WARP verify
bse-help()   { ... }
bse-ip-add() { echo "$1" >> "$BSE_IP_LIST"; }

SOCKS vs SOCKS5 — giải thích

SOCKS là protocol proxy ở tầng TCP — chuyển tiếp kết nối TCP từ client qua proxy server đến đích. Không quan tâm nội dung traffic (HTTP, RDP, MySQL, ...). Khác với HTTP proxy (chỉ HTTP/HTTPS).

SOCKS4

SOCKS (không có version)

Phiên bản đầu tiên. Chỉ hỗ trợ TCP. Không hỗ trợ authentication và không hỗ trợ UDP.

Trong PAC file: "SOCKS host:port" — browser thường hiểu là SOCKS4.

Phiên bản cải tiến. Hỗ trợ authentication (user/pass), UDP, và IPv6.

Trong PAC file: "SOCKS5 host:port" — Chrome chấp nhận.

socks5h:// = DNS resolve ở proxy server (remote DNS) — quan trọng cho Access policies.

Tại sao PAC dùng cả hai?

Chrome

Hiểu "SOCKS5". DNS resolve ở proxy side (remote DNS). Nếu PAC trả "SOCKS", Chrome có thể hiểu là SOCKS4.

Safari

Yêu cầu "SOCKS". Bỏ qua silently nếu PAC trả "SOCKS5" — traffic đi DIRECT thay vì qua proxy.

Fix

Return cả hai cách: "SOCKS5 127.0.0.1:1080; SOCKS 127.0.0.1:1080". Browser thử cái đầu, fail thì thử cái thứ hai (PAC failover).

socks5 vs socks5h (trong env vars / curl):
socks5://127.0.0.1:1080 — DNS resolve ở client (local DNS). Có thể leak DNS, Access policies không match.
socks5h://127.0.0.1:1080 — DNS resolve ở proxy server (remote DNS). An toàn, không leak. Luôn dùng socks5h:// trong HTTPS_PROXY.

Gotchas đã fix (verified):
1. file:// PAC không hoạt động → serve qua HTTP (:8799)
2. SOCKS5 vs SOCKS → return cả hai "SOCKS5 ...; SOCKS ..."
3. IP literal matching → triple match shExpMatch + isInNet
4. PAC chỉ HTTP → RDP/SSH/MySQL cần bse-forward (SSH -L)
5. Network detect → auto từ route -n get default
6. Bypass list → không include 172.16/12 (backseat ở 172.25.x)
7. wrangler crash → unset HTTPS_PROXY trước khi deploy
