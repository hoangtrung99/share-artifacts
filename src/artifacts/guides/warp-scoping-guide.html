Tùy Chọn Cloudflare WARP Không Cần Admin

routing có chọn lọc cho macOS — 4 cách tiếp cận

Tình huống: bạn bắt buộc dùng Cloudflare WARP của công ty để truy cập dịch vụ (AWS, private apps), nhưng không muốn WARP ảnh hưởng toàn bộ mạng máy. Bạn không có quyền admin trên Zero Trust dashboard, và dịch vụ là public service (như AWS) — chỉ cần egress IP đúng + posture "WARP connected".

Tài liệu này trình bày 4 cách để giải quyết, từ tối ưu nhất đến fallback.

Tổng quan 4 cách
Cách Nguyên lý Thiết bị phụ Host network UX Khuyến nghị

B — Android Tailscale Proxy Giống A, nhưng Mac n → Android qua tailnet (mesh VPN). Android (tailnet) Sạch 100% Host browser + PAC Phức tạp hơn A

Chọn cách nào?
Có Android?
Có — chọn Cách A (Android SSH Proxy). Đơn giản, ổn định, dùng host browser.
Có + muốn kết nối qua tailnet — chọn Cách B (Android Tailscale Proxy). Phức tạp hơn nhưng kết nối mọi nơi, không cần cùng WiFi/USB.
Không?
Chọn Cách C (VM Isolation — UTM). Cài WARP trong VM, host sạch hoàn toàn.
Cần nhanh?
Chọn Cách D (Toggle On/Off). Bật WARP khi cần, tắt khi xong. Không tối ưu nhưng không cần setup.
Ràng buộc đã xác nhận:
  • Dịch vụ: public service (AWS) — chỉ cần egress IP + posture "WARP connected"
  • Không cần host-specific posture signals (disk encryption, EDR, managed cert)
  • Không có quyền admin Zero Trust dashboard
  • Bắt buộc dùng Cloudflare công ty
Cả 4 cách thỏa mãn
Cách A — Android SSH Proxy

Android chạy Cloudflare WARP (VpnService — capture toàn bộ outbound traffic) + SimpleSSHD (SSH server port 2222). Mac kết nối qua SSH dynamic forwarding (ssh -D) tạo SOCKS5 proxy local. Chỉ app nào trỏ vào proxy mới đi qua WARP.

Root không cần thiết. SimpleSSHD chạy trên port 2222 (unprivileged).

Tại sao hoạt động: Android VpnService (WARP) tạo TUN interface capture toàn bộ outbound traffic. SimpleSSHD nhận connection từ Mac, forward ra internet — phần outbound đó đi qua WARP tunnel tự động. Inbound (Mac → Android) không bị capture.
Bước 1 — Android

Cài WARP + enroll

Cài Cloudflare One Agent từ Google Play. Mở app, login bằng credentials công ty. WARP tự kết nối.

# Verify trên Android (nếu có Termux): curl https://www.cloudflare.com/cdn-cgi/trace # Kết quả: warp=on
Bước 2 — Android

Cài SimpleSSHD

Tải từ F-Droid hoặc galexander.org/software/simplesshd. Mở app, start server (port 2222).

Copy public key SSH Mac vào SimpleSSHD (authorized_keys). SimpleSSHD dùng public-key auth only.

Bước 3 — Mac

Kết nối SSH tunnel

WiFi: cả 2 cùng mạng

ssh -D 1080 -N -p 2222 <android-ip>

USB (khuyên dùng):

adb forward tcp:2222 tcp:2222 ssh -D 1080 -N -p 2222 localhost
# ~/.ssh/config cho ổn định: Host android-warp HostName localhost Port 2222 DynamicForward 1080 ServerAliveInterval 60
Bước 4 — Mac

Trỏ app vào proxy

Browser: SOCKS5 proxy → 127.0.0.1:1080

Critical: dùng socks5h:// (remote DNS), KHÔNG dùng socks5:// (local DNS). Remote DNS đảm bảo Access policies match và không leak DNS.

PAC file (chỉ route domain cụ thể):

// proxy.pac function FindProxyForURL(url, host) { if (shExpMatch(host, "*.aws.amazon.com") || shExpMatch(host, "*.console.aws.amazon.com")) return "SOCKS5 127.0.0.1:1080"; return "DIRECT"; }
Verify
# Qua proxy — phải thấy warp=on curl --socks5-hostname 127.0.0.1:1080 https://www.cloudflare.com/cdn-cgi/trace # Direct (không proxy) — phải thấy warp=off (host sạch) curl https://www.cloudflare.com/cdn-cgi/trace
Cách B — Android Tailscale Proxy

Giống Cách A, nhưng Mac kết nối đến Android qua Tailscale tailnet thay vì WiFi/USB. Lợi ích: kết nối mọi nơi, không cần cùng mạng, encrypted mesh.

Thách thức: Android chỉ cho phép một VpnService cùng lúc. Tailscale app tiêu chuẩn và WARP đều dùng VpnService — xung đột. Giải pháp: chạy Tailscale ở chế độ userspace networking (không dùng VpnService).

Conflictt xác nhận: Tailscale app tiêu chuẩn + WARP = không thể chạy cùng lúc trên Android. Cả hai đều dùng VpnService. Android chỉ cho phép 1 VpnService active.

Nguồn: Tailscale FAQ: Other VPNs, GitHub #410, GitHub #15288
Giải pháp

Tailscale Userspace Networking + WARP

Chạy Tailscale không dùng VpnService — dùng userspace networking mode. WARP giữ VpnService. Không xung đột.

1 TailSocks (không cần root)

App Android chạy Tailscale ở userspace mode (tsnet). Built-in SOCKS5 proxy. Không xung đột WARP.

# Cài TailSocks APK # GitHub: bropines/tailsocks # Login tailnet → nhận tailnet IP # Built-in SOCKS5 proxy local

2 Magisk tailscaled (có root)

Magisk module chạy tailscaled daemon userspace. hev-socks5-tunnel expose proxy.

# tailscaled userspace mode: tailscaled --tun=userspace-networking \ --socks5-server=localhost:1080 tailscale up --auth-key=<key>

Bước 1 — Android

WARP + TailSocks (hoặc tailscaled)

Cài WARP bình thường (Cách A bước 1). Sau đó cài TailSocks (FOSS, userspace Tailscale) hoặc Magisk tailscaled module.

Bước 2 — Android

Forward tailnet → SimpleSSHD

Trong TailSocks/tailscaled, forward incoming tailnet traffic port 2222 đến SimpleSSHD local:

tailscale serve --tcp 2222 tcp://localhost:2222

Hoặc nếu dùng TailSocks built-in SOCKS5 proxy, forward port đó thay thế.

Bước 3 — Mac

SSH qua tailnet

Cài Tailscale trên Mac, join cùng tailnet.

# Mac SSH đến Android qua tailnet IP ssh -D 1080 -N -p 2222 <android-tailnet-ip> # Verify tailnet connectivity tailscale status # Phải thấy Android device online
Bước 4 — Mac

Trỏ app + verify (giống Cách A bước 4)

SOCKS5 proxy 127.0.0.1:1080 + PAC file + verify warp=on.

Cách B vs Cách A: Tailscale thêm latency (mesh relay) nhưng giải phóng khỏi WiFi/USB. Nếu Mac và Android luôn cùng WiFi/USB — Cách A đơn giản hơn. Nếu cần kết nối từ xa (khác mạng) — Cách B là lựa chọn duy nhất.

Bước 1

Cài UTM + tạo VM

brew install --cask utm

Tải Ubuntu 24.04 Desktop ARM64 ISO. UTM → New VM → Virtualize (không Emulate) → ARM64.

RAM: 4GB, CPU: 2 cores, Disk: 20GB.

Bước 2

Trong VM — cài WARP

# Thêm repo Cloudflare curl -fsSL https://pkg.cloudflareclient.com/pubkey.gpg \ | sudo gpg --yes --dearmor \ -o /usr/share/keyrings/cloudflare-warp-archive-keyring.gpg echo "deb [arch=arm64 signed-by=/usr/share/keyrings/cloudflare-warp-archive-keyring.gpg] https://pkg.cloudflareclient.com/ $(lsb_release -cs) main" \ | sudo tee /etc/apt/sources.list.d/cloudflare-client.list sudo apt update && sudo apt install -y cloudflare-warp
Bước 3

Enroll + làm việc trong VM

# Enroll team công ty (mở browser trong VM) warp-cli registration new <team-cong-ty> warp-cli connect # Verify curl https://www.cloudflare.com/cdn-cgi/trace # warp=on

Mở browser trong VM → truy cập AWS. Host macOS hoàn toàn sạch.

Resource

RAM: ~2GB idle, ~3GB khi dùng browser.
CPU: ~0% idle (native virtualization).
Disk: ~8GB.

Ưu điểm

Không cần Android. Enrollment interactive đơn giản. Posture check pass tự nhiên.

Nhược điểm

AWS work trong VM browser (không phải host browser). Tốn RAM/disk.

Cách D — Toggle On/Off (Fallback)

Không setup phức tạp. Bật WARP khi cần AWS, tắt khi xong. Giảm blast radius theo thời gian — WARP chỉ ảnh hưởng toàn mạng khi bạn đang cần AWS.

# Bật WARP khi cần AWS warp-cli connect # Tắt WARP khi xong warp-cli disconnect # Kiểm tra trạng thái warp-cli status

Aliases cho nhanh (thêm vào ~/.zshrc hoặc ~/.bashrc):

# Alias nhanh alias won='warp-cli connect' alias woff='warp-cli disconnect' alias wstatus='warp-cli status'
Hạn chế: Khi WARP on, toàn bộ traffic máy đi qua WARP — không chỉ AWS. Nếu session AWS cần WARP liên tục (egress IP allowlist), bạn phải giữ WARP on suốt phiên.

Lưu ý quan trọng
1. DNS Leak — LUÔN dùng socks5h://
Dùng socks5h:// (remote DNS resolution) thay vì socks5:// (local DNS). Remote DNS đảm bảo: (a) DNS queries đi qua WARP, (b) Access policies match đúng, (c) không leak DNS ra ngoài.
2. Posture Check — chỉ hoạt động nếu
Công ty chỉ require "WARP connected" posture hoặc egress IP allowlist. Không hoạt động nếu posture check yêu cầu host-specific signals (disk encryption, EDR agent, managed-device cert) — Android/VM sẽ fail posture và bị block Access.
3. Performance — chấp nhận được cho console/API
WiFi/USB latency + WARP tunnel overhead. Phù hợp cho AWS console, API calls. Có thể chậm cho download lớn hoặc streaming.
4. SSH Timeout — thêm keepalive
Thêm ServerAliveInterval 60 vào SSH config để tránh timeout khi idle.
Checklist verify
  • WARP connected trên Android/VM — app hiện "Connected"
  • SSH tunnel established — không lỗi, ssh -D 1080 -N -p 2222 ... chạy không error
  • curl --socks5-hostname 127.0.0.1:1080 https://www.cloudflare.com/cdn-cgi/trace hiện warp=on
  • curl https://www.cloudflare.com/cdn-cgi/trace (direct, không proxy) hiện warp=off
  • Browser qua proxy vào được AWS
  • Browser không qua proxy không đi qua WARP (kiểm tra IP tại ipleak.net)
  • DNS resolve qua proxy — dùng socks5h://, verify DNS server tại dnsleaktest.com
