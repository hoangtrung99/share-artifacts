Selective WARP routing · Apple container · userspace WireGuard

bse-on — một lệnh, định tuyến chọn lọc qua WARP

Một container Linux siêu nhẹ trên Apple container chạy wireproxy (WireGuard ở user-space). Nó phơi ra một SOCKS5 cục bộ; macOS dùng PAC để chỉ đẩy đúng các đích cần thiết (AWS, mạng nội bộ) qua WARP, còn lại đi thẳng. RDP/SSH/MySQL được forward bằng TCP tunnel ngay trong container.

01 — Khái quát

bse-on làm gì

Gõ bse-on, ba việc xảy ra tuần tự, mỗi việc một dòng đơn giản:

① Sinh config & dựng container

bse-wp-genconf đọc bse-forward.conf → viết wireproxy.conf; container bse-wp khởi động từ image bse-wireproxy:latest, publish các cổng về 127.0.0.1.

② Bật PAC + CLI proxy

Một PAC file phục vụ tại 127.0.0.1:8788 được gắn làm auto-proxy của macOS; biến môi trường HTTPS_PROXY=socks5h://127.0.0.1:1080 cho CLI.

③ Lưu lượng đi đúng đường

Trình duyệt & CLI hỏi PAC: đích thuộc danh sách AWS / nội bộ → đi SOCKS 127.0.0.1:1080 → container → WireGuard tới org WARP → Cloudflare → đích. Mọi thứ khác đi thẳng, không qua proxy. RDP/SSH/MySQL nối vào cổng loopback (vd 127.0.0.1:13389) và được tunnel qua cùng đường WARP.

04 — Enroll: API-direct sinh teams.conf

Một POST có JWT → teams.conf

Enroll chạy thẳng trên Mac bằng enroll.sh (chỉ cần openssl + curl + jq) — không warp-svc daemon, không container. Nó gọi đúng API đăng ký thiết bị của Cloudflare, gắn JWT của org. Cờ --with-container là fallback: chạy cùng enroll.sh bên trong image khi Mac thiếu tool. Registration vĩnh viễn → teams.conf tái dùng lâu dài, không enroll lại liên tục.

1 · JWT
Mở https://<team>.cloudflareaccess.com/warp → login SSO → trang Success. COPY token (Copy Link); clipboard-watcher tự bắt khi clipboard đổi — không dán terminal (token ~1 KB bị zsh cắt cụt).
│ JWT sống ~60 s → dùng ngay
2 · keygen + POST /reg
openssl sinh cặp khoá X25519, rồi POST api.cloudflareclient.com/v0a2483/reg với header Cf-Access-Jwt-Assertion: <JWT> + public key.
│ response 200 = JSON phẳng (.config ở top-level)
3 · ghi teams.conf
Map response → config WireGuard chuẩn cho wireproxy (private key chmod 600, không in ra). account_type=team xác nhận đã gắn org.

Mapping schema (đã verify từ response /reg thật)

NguồnĐích (teams.conf)
openssl X25519 private (DER 32B → base64)[Interface] PrivateKey
.config.interface.addresses.v4 / .v6[Interface] Address (/32, /128)
.config.peers[0].public_key[Peer] PublicKey (peer Cloudflare)
.config.peers[0].endpoint.host + .ports[0][Peer] Endpoint — port thật 2408 (lưu ý endpoint.v4 trả port 0 placeholder)
MTU 1280WARP cần MTU ~1280; wireproxy mặc định 1420 sẽ treo TLS/AWS. teams.conf luôn ghi MTU = 1280.
05 — Định tuyến chọn lọc

Cái gì đi WARP, cái gì đi thẳng

PAC + socks5h (trình duyệt & CLI)

PAC chỉ trả về proxy cho các đích trong danh sách (AWS ranges, domain nội bộ, 10.0.0.0/16). socks5h giải DNS phía proxy → không rò DNS, tên nội bộ resolve đúng.

TCP tunnel (RDP/SSH/MySQL)

Mỗi dòng trong bse-forward.conf thành một [TCPClientTunnel]: cổng loopback cục bộ → đích nội bộ, đi qua WARP. Nối RDP tới 127.0.0.1:13389 là chạm tới máy nội bộ.

~/.proxy/bse-forward.conf (ví dụ — IP đã ẩn danh)
# name   host          rport  [lport]
rdp     10.0.0.10     3389
ssh     10.0.0.10     22
mysql   10.0.0.10     3306
ssh-cb  203.0.113.20  22     10023

lport mặc định = 10000 + rport (rdp→13389, ssh→10022, mysql→13306); cột 4 ghi đè (ssh-cb→10023). Cùng công thức dùng ở cả publish-args lẫn wireproxy.conf nên cổng publish luôn khớp cổng tunnel.

06 — Toàn bộ code

Các file tạo nên bse-on

Cây thư mục: ~/.proxy/container/ chứa toàn bộ phần wireproxy; ~/.proxy/bse-aliases.sh định nghĩa bse-on và nạp backend.

container/Containerfile
# wireproxy = userspace WireGuard → SOCKS5 + TCP tunnels.
FROM alpine:3.20
ARG WIREPROXY_VERSION=v1.1.2
ARG TARGETARCH=arm64
RUN apk add --no-cache ca-certificates wget \
 && wget -O /tmp/wp.tar.gz \
      "https://github.com/windtf/wireproxy/releases/download/${WIREPROXY_VERSION}/wireproxy_linux_${TARGETARCH}.tar.gz" \
 && tar -xzf /tmp/wp.tar.gz -C /usr/local/bin wireproxy \
 && rm /tmp/wp.tar.gz && /usr/local/bin/wireproxy --version
COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
# /data (mount từ Mac): teams.conf (enroll) + wireproxy.conf (genconf)
ENTRYPOINT ["/entrypoint.sh"]
container/entrypoint.sh (PID 1 trong container)
#!/bin/sh
set -e
CONF=/data/wireproxy.conf
WG=/data/teams.conf
if [ ! -f "$WG" ]; then echo "✗ Thiếu $WG — chạy bse-wp-enroll"; exit 1; fi
if [ ! -f "$CONF" ]; then echo "✗ Thiếu $CONF — chạy bse-wp-genconf"; exit 1; fi
exec wireproxy -c "$CONF"
container/bse-wireproxy.sh · biến + dựng cổng (security fix)
BSE_WP_NAME="bse-wp"
BSE_WP_IMAGE="bse-wireproxy:latest"
BSE_WP_ENROLL_SH="$HOME/.proxy/container/enroll.sh"   # enroll API-direct (Mac); container chỉ là fallback
BSE_WP_DATA="$HOME/.proxy/container/warp-data"
BSE_WP_PROXY_PORT=1080
BSE_WP_PAC_PORT=8788

# Build "-p host:ctr" cho SOCKS + mọi forward. Bind 127.0.0.1 → KHÔNG lộ ra LAN.
_bse_wp_publish_args() {
  printf -- "-p 127.0.0.1:%s:%s " "$BSE_WP_PROXY_PORT" "$BSE_WP_PROXY_PORT"
  [ -f "$BSE_FORWARD_CONF" ] || return 0
  local name ip rport lport _rest
  while read -r name ip rport lport _rest; do
    case "$name" in ''|\#*) continue ;; esac
    [ -n "$rport" ] || continue
    [ -z "$lport" ] && lport=$((10000 + rport))
    printf -- "-p 127.0.0.1:%s:%s " "$lport" "$lport"
  done < "$BSE_FORWARD_CONF"
}
container/enroll.sh · enroll API-direct (dùng chung Mac & container)
# openssl X25519 keygen → POST /reg với JWT → teams.conf. POSIX sh; chạy trên Mac (mặc định)
# hoặc trong image khi --with-container. Chỉ cần openssl + curl + jq.
JWT="$1"; OUT_DIR="$2"; body=$(mktemp); TOS=$(date -u +%Y-%m-%dT%H:%M:%S.000Z)
key=$(mktemp); openssl genpkey -algorithm X25519 -out "$key"
PRIV=$(openssl pkey -in "$key" -outform DER | tail -c 32 | base64)
PUB=$(openssl pkey -in "$key" -pubout -outform DER | tail -c 32 | base64)
# gắn device vào org qua header Cf-Access-Jwt-Assertion
code=$(curl -sS -m20 --compressed -o "$body" -w '%{http_code}' -X POST \
  "https://api.cloudflareclient.com/v0a2483/reg" \
  -H "CF-Client-Version: a-6.10-2158" -H "Cf-Access-Jwt-Assertion: $JWT" \
  -d "{\"key\":\"$PUB\",\"tos\":\"$TOS\",\"model\":\"Linux\",\"type\":\"Linux\"}")
if [ "$code" != 200 ]; then echo "✗ /reg HTTP $code (401=JWT hết hạn)"; exit 2; fi
# response 200 = JSON phẳng: .config ở top-level (response lỗi mới bọc envelope)
A4=$(jq -r '.config.interface.addresses.v4 // empty' "$body")
PEER=$(jq -r '.config.peers[0].public_key // empty' "$body")
EP_IP=$(jq -r '.config.peers[0].endpoint.v4 // empty' "$body" | sed 's/:[0-9]*$//')
EP_PORT=$(jq -r '.config.peers[0].endpoint.ports[0] // 2408' "$body")  # endpoint.v4 trả :0 placeholder
# → ghi teams.conf: PrivateKey=$PRIV · Endpoint=$EP_IP:$EP_PORT · MTU 1280 · chmod 600
container/bse-wireproxy.sh · bse-wp-enroll: clipboard-watcher + --with-container
bse-wp-enroll() {   # [--with-container] <team>
  local use_ctr=0; [ "$1" = "--with-container" ] && { use_ctr=1; shift; }
  local team="$1" jwt
  open "https://$team.cloudflareaccess.com/warp"   # login SSO → trang Success
  # COPY token (Copy Link) — watcher tự bắt khi clipboard đổi; fallback dán tay
  jwt=$(_bse_wp_wait_jwt 120) || jwt=$(_bse_wp_manual_paste) || return 1
  if [ "$use_ctr" = 1 ]; then   # fallback: enroll trong image (Mac thiếu openssl/curl/jq)
    container run --rm -v "$BSE_WP_DATA:/data" --entrypoint /enroll.sh "$BSE_WP_IMAGE" "$jwt" /data
  else                       # mặc định: enroll ngay trên Mac
    "$BSE_WP_ENROLL_SH" "$jwt" "$BSE_WP_DATA"
  fi
}
container/bse-wireproxy.sh · genconf + start
bse-wp-genconf() {   # bse-forward.conf → wireproxy.conf
  { echo "WGConfig = /data/teams.conf"; echo; echo "[Socks5]"
    echo "BindAddress = 0.0.0.0:$BSE_WP_PROXY_PORT"; } > "$BSE_WP_DATA/wireproxy.conf"
  while read -r name ip rport lport _rest; do
    # ... mỗi đích → [TCPClientTunnel] BindAddress=0.0.0.0:$lport Target=$ip:$rport
  done < "$BSE_FORWARD_CONF"
}

bse-wp-start() {
  # khớp TÊN chính xác (^bse-wp[space]) — substring grep sẽ nhầm bse-wp-enroll là bse-wp
  _bse_wp_running && { echo "đã chạy"; return 0; }
  bse-wp-genconf
  local pub; pub=$(_bse_wp_publish_args)
  eval "container run -d --name \"$BSE_WP_NAME\" $pub -v \"$BSE_WP_DATA:/data\" \"$BSE_WP_IMAGE\""
}
bse-aliases.sh · bse-on uỷ quyền cho backend container
# Nạp backend wireproxy (định nghĩa mọi bse-wp-*)
[ -f "$HOME/.proxy/container/bse-wireproxy.sh" ] && source "$HOME/.proxy/container/bse-wireproxy.sh"

bse-on() {
  command -v bse-wp-on >/dev/null 2>&1 || { echo "✗ thiếu backend"; return 1; }
  bse-wp-genconf >/dev/null 2>&1   # đồng bộ forwards
  bse-wp-rm      >/dev/null 2>&1   # idempotent: bỏ container cũ
  bse-wp-on                       # start + PAC on + CLI on + status
}
bse-off() { bse-wp-off; }
07 — Bảo mật & tài nguyên

Vì sao thiết kế này an toàn & nhẹ

🔒 Chỉ loopback

Mọi cổng publish bind 127.0.0.1, không phải 0.0.0.0 → máy khác trong LAN không dùng được egress công ty hay tunnel nội bộ. PrivateKey chỉ nằm trong teams.conf (chmod 600), không bao giờ in ra / commit.

⚡ Nhẹ máy

Image 9.4 MB, một binary Go tĩnh, RSS sống ~59 MB. Apple container = một micro-VM/ container, idle ~100 MB — nhẹ hơn nhiều so với chạy một Docker Desktop full.

KIỂM CHỨNG EGRESSwarp=on chưa đủ. Bằng chứng thật là chạm được resource bị allowlist: RDP/SSH vào 10.0.0.0/16 hay AWS console mở được. bse-wp-status in egress IP để đối chiếu allowlist công ty.
DOCKER PORTABILITYVì wireproxy là userspace (không cap/device), image chạy nguyên trên Docker/OrbStack với -v + -p 127.0.0.1:…. Chỉ khác bước build: docker build -f Containerfile (Docker không thấy image của Apple container daemon).
