Mission

Restrict VPC Endpoint access from Full Access (*) to role-based least-privilege policies. Each endpoint gets a policy document that limits which IAM roles (principals) can use it. This prevents unauthorized services or compromised roles from reaching AWS APIs through VPC endpoints.

8 — Terraform Implementation

Role-centric model: input is a map of role_name → [groups], reverse-mapped to group → [role_ARNs] for policy documents. Branch: work/endpoint • Commit: 0f43479

variables.tf

Single input variable: role_endpoint_access. Validation via setsubtract ensures only valid group names.

1 variable (was 7)
locals.tf

2-step reverse mapping. all_groups extracts unique group names, group_principals builds ARN lists per group.

15 lines
policies.tf

8 named aws_iam_policy_document data sources. 6 simple (principal-only), 2 special (STS, Storage).

193 lines
variables.tf — role_endpoint_access 
variable "role_endpoint_access" {
  description = "Map of IAM role name to list of endpoint policy groups it may access"
  type        = map(list(string))
  default     = {}

  validation {
    condition = length(setsubtract(
      toset(flatten(values(var.role_endpoint_access))),
      ["messaging", "secrets", "storage", "container", "compute", "ssm", "observability"]
    )) == 0
    error_message = "Each group must be one of: messaging, secrets, storage, container, compute, ssm, observability."
  }
}
locals.tf — reverse mapping 
locals {
  account_id      = data.aws_caller_identity.current.account_id
  role_arn_prefix = "arn:aws:iam::${local.account_id}:role"

  # All unique group names from role_endpoint_access values
  all_groups = toset(flatten(values(var.role_endpoint_access)))

  # Reverse mapping: group -> [role ARNs that have this group]
  group_principals = {
    for group in local.all_groups : group => [
      for role, groups in var.role_endpoint_access :
      "${local.role_arn_prefix}/${role}" if contains(groups, group)
    ]
  }
}

Design principle: Each role appears exactly once in tfvars with all its groups listed. Adding a new role = one line. Changing access for an existing role = edit one line. The reverse mapping in locals.tf automatically updates all affected policy documents.
9 — Special Cases
STS + IRSA

Problem

IRSA calls sts:AssumeRoleWithWebIdentity using a JWT token from EKS OIDC provider — no IAM credentials. If the endpoint policy requires aws:PrincipalAccount, the request is denied because there's no principal account context.

Solution

STS policy uses 2 statements:

1. sts:AssumeRoleWithWebIdentity → Principal * (no condition)
2. sts:* → Principal AWS:* with aws:PrincipalAccount condition
S3 Gateway + ECR Image Pull

Problem

ECR image pulls download layers from S3. The pre-signed URL is signed by ECR service principal (AWS-owned account), not the customer account. If S3 policy only allows customer principals → image pull fails → CrashLoopBackOff.

Solution

Storage policy adds a special statement:

Allow s3:GetObject from arn:aws:s3:::prod-ap-northeast-1-starport-layer-bucket/* Principal: * (no account condition)
Secondary finding: point-app-irsa-role has AmazonKinesisFullAccess attached but no code uses Kinesis. This unused policy should be reviewed for removal in a separate security task.
