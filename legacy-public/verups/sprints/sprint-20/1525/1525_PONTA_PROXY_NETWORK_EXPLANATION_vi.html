BB-1525 - Giải thích đường mạng PONTA

PONTA direct path vs proxy path | cập nhật 2026-03-06

1. Kết luận trực tiếp
Trả lời câu hỏi STG

Không cần bắt buộc mở 28443 và 8443 nếu stg runtime đi proxy. Ở mức pod, network path đi tới 10.51.187.96:3128.

Điểm dễ nhầm

login-url chỉ là URL redirect cho browser. Đừng dùng riêng nó để kết luận pod cần egress. Cái quyết định egress thật là if1507, if1511, webIf.

Lưu ý: giữ 8443/28443 trên stg vẫn có thể hợp lý nếu team muốn direct-path diagnostics hoặc fallback direct path. Nhưng theo đúng runtime path hiện tại thì 3128 là rule bắt buộc.

3. Luồng mạng hoạt động như thế nào

Direct path

  • App giữ target URL là :28443 hoặc :8443
  • HTTP client mở TCP trực tiếp tới host đích
  • Pod NetworkPolicy phải allow đúng port đích
  • Áp dụng cho dev hiện tại và prd current code state
→

Proxy path

  • App vẫn giữ logical URL là :28443 / :8443
  • Nhưng client được set proxy
  • Pod mở TCP tới proxy:3128
  • Proxy mới là bên đi tiếp tới PONTA
Ý nghĩa thực tế cho STG: nếu app vào nhánh proxy thì pod chỉ cần đi được tới 10.51.187.96:3128. NetworkPolicy ở mức pod không cần nhìn thấy 28443/8443 để app runtime hoạt động.
4. Bằng chứng code

`login-url` chỉ là redirect

Ví dụ từ controller:

String redirectUrl =
        UriComponentsBuilder.fromUriString(pontaConfig.getLoginUrl())
                .queryParams(queryParams)
                .build()
                .toUriString();
log.info("redirect to ponta login screen, url: {}", redirectUrl);
response.sendRedirect(redirectUrl);

Đây là redirect cho browser/client; không có outbound HTTP từ pod tới login-url.

`if1507` / `if1511` là outbound thật

Service gọi thật và request util POST thật:

String accessToken = pontaRequestUtil.if1507(secretCode);
String memberId = pontaRequestUtil.if1511(accessToken);

response =
        restTemplate.postForObject(
                pontaConfig.getIf1507Url(), requestEntity, String.class);

Các request này dùng RestTemplate.postForObject(...), vì vậy đây là egress thật từ server.

`webIf-Url` cũng là outbound thật

Ví dụ từ `PontaBizInVokerApi`:

response =
        restTemplate.postForObject(
                pontaConfig.getWebIfUrl(), requestEntity, String.class);
log.info("if001 response:{}", response);

Nếu không dùng proxy, webIf yêu cầu direct 8443. Nếu dùng proxy, pod chỉ cần đi được tới proxy.

Proxy chỉ active cho `stg`

Nhánh bật proxy trong code:

CloseableHttpClient httpClient;
if (point.common.constant.Environment.stg.name().equals(activeProfile)) {
    HttpHost proxy = new HttpHost(stgProxyHost, stgProxyPort);
    RequestConfig config = RequestConfig.custom().setProxy(proxy).build();
    httpClient =
            HttpClients.custom()
                    .setSSLSocketFactory(sslConnectionSocketFactory)
                    .setDefaultRequestConfig(config)
                    .build();
}

Đây là lý do vì sao stg đi proxy, còn dev và prd hiện tại vẫn là direct path dù config có thể có field proxy.

5. Hàm ý cho NetworkPolicy
Rule bắt buộc

STG current runtime: allow 10.51.187.96/32:3128

DEV current runtime: allow 8080

PRD current code: allow direct 28443 và 8443

Rule phụ

8443/28443 trên stg chỉ là rule phụ nếu team muốn:

  • direct-path probe
  • fallback direct path
  • giữ room cho thay đổi đối tác mà chưa muốn đổi policy ngay
6. Ghi chú khi triển khai PRD

Deployment note

  • Không copy rule dev 8080 sang prd.
  • Với current code state, prd vẫn là direct path nên policy runtime cần 28443 và 8443.
  • Nếu muốn prd đi proxy, phải sửa cả code/profile handling, không chỉ sửa policy.
  • Precheck thêm: point-worker `application-prd.yaml` còn webIf-Url: #TBD.
Điểm chốt: ở mức pod NetworkPolicy, ta luôn mở theo đường kết nối TCP thực tế của pod, không mở theo mọi URL logic có trong config.
