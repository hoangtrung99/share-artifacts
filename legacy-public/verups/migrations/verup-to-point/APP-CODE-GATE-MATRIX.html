scoped apply · critical

security_group — apply scope must be restricted

The ported release/verup version of security_group contains 3 destructive changes against currently-deployed point infrastructure. Phase 3a must use -target to apply only the 4 NEW resources (2 SGs from BB-1514 cd-runner work + 2 new ingress rules referencing them). The full module apply is deferred to Phase 3b immediately before aurora.

File Destructive change Impact if full apply runs early

mysql.tf Port literal 3306 replaced by var.mysql_port = 13306 (BB-1901 hardening) Aurora SG rule flips to 13306 → cuts live MySQL connectivity until aurora component apply
ec2_bastion.tf New egress rules use var.mysql_port = 13306 Same as above — bastion egress targets wrong port until aurora flip
