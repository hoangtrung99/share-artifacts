## Risks / points to be careful about *(verbatim from Confluence)*

1. **IP address shortage** — ALB can go down if the subnet has fewer than 8 available IP addresses. Point stg/prd have significantly smaller CIDR.
2. **Ponta connection check** — existing resources should be kept intact (VGW routing, CoreDNS config, etc.).
3. **Frontend resources** — STG customer-frontend has resources that were manually created and need to remain intact (proxy for verup stg, OAuth-related). PRD does not have this setup.
4. **WAF deployment impact** — WAF (customer) deployment will lead to maintenance termination/interruption. Need to think through and align on how to handle this operationally.
5. **Restriction for prd access (IAM)** — need to confirm ESS IP addresses in advance.

## Coordination with app *(verbatim from Confluence)*

1. **ci/cd** — (a) provide env resource values for app to set up the pipeline (distribution id / s3 bucket name etc) in advance; (b) create new cicd secrets if needed (depends on whether they use the existing repo).
2. **eventbridge** — (a) after the infra/iam has been deployed, app can start work on the eventbridge part; (b) stop necessary eventbridge rules before the real release (preventing unexpected data manipulation).
3. **shut down backend before release** — after turning off eventbridge, also scale all backend pods to 0 (they might get restarted during the deploy; shut down immediately to avoid unexpected interruption to other tasks).
4. **data migration** — (a) after the infra/iam has been deployed, app can start DMS preparation (DMS console operation), admin role needed; (b) after ec2-data-transfer has been set up, notify app to test their data-migration shell scripts.
