The 4-layer network model — where ports block each other

port truly open  ⇔  SG allows  ∧  NACL allows  ∧  NetworkPolicy allows  ∧  (ingress) ALB listener + cert + controller wired
Layer A — Security Groups the real intra-VPC enforcement

Where almost all mutual-blocking lives: ALB swap alb-sg→alb-https-sg (DependencyViolation), mysql 3306→13306, ALB→pod 8080 repoint gap (G4), VPC-endpoints 587 add, bastion rule rework.

Layer B — Network ACLs permissive intra-VPC — NOT a per-port blocker

Verified vpc/nacl.tf:71: private inbound = protocol "-1" blanket-allow for 172.18.0.0/16 (live-confirmed). 13306/443/587/8080/Redis/Redshift all pass NACL intra-VPC. Only the public internet edge (443/80/SSH/ephemeral) is port-specific. The "SG fixed but NACL still blocks" class does NOT apply here.

Layer C — Kubernetes NetworkPolicy pod-level enforcement

default-deny + allow-dns/internal/vpc (CIDR 172.18.0.0/16 = live VPC, correct). G-N3 bug: k8s_apply.sh:179 applies default-deny FIRST → transient DNS/egress drop; move it to the LAST -f arg.

Layer D — Controller / Ingress ALB listener + cert wiring

ALB SG swap is controller-driven (kubectl apply ingress.yaml, NOT elbv2 set-security-groups). The 443 listener needs an ISSUED regional ap-northeast-1 ACM cert (G11) + the controller pointed at the right VPC (G9).

The three network choreographies (where ports/SG/ingress block each other)

A · ALB SG swap (DependencyViolation + 8080 gap)

  1. Pre-gate G9 (vpcId) + G11 (regional ACM cert) — else no 443 listener, swap stalls.
  2. apply -target=aws_security_group.alb_https + add alb-https-sg→8080 rule while keeping alb-sg→8080 (G4 fix).
  3. kubectl apply ingress.yaml → controller re-attaches ALB + flips listener 80→443.
  4. Poll-gate (Q1): wait until ALB SecurityGroups no longer contains sg-005… (not "== alb-https-sg exactly").
  5. full apply → removes detached alb-sg + the transient alb-sg→8080 rule.
Naive destroy of alb-sg (3 live ENIs) → DependencyViolation. Single 8080 repoint with pods up → ALB→pod drop in the swap gap. Best: run inside the pods=0 window.

B · EKS auth-bridge (group-mapping → lockout risk)

  1. Stage-1: CONFIG_MAP → API_AND_CONFIG_MAP (both modes work).
  2. Apply k8s rbac (admin→cluster-admin binding) + aws-auth WHILE both modes work.
  3. Verify kubectl get clusterrolebinding admin-cluster-admin + access entry resolves as bs-developer.
  4. Stage-2: → API (one-way) — ONLY after verify passes.
G3-EKS-ORDER (verified): access entries use kubernetes_groups + enable_cluster_creator_admin_permissions=false; group "admin" has no cluster-admin until the binding lands. tfvars group_names.administrator="admin" == binding subject → fix genuinely prevents lockout. Never direct CONFIG_MAP→API.

C · Stateful window (port flip + single scale-to-0)

  1. ONE capture + scale-to-0 (G8). Freeze CI/CD (cd_runner Flyway — Q3).
  2. redshift FIRST (longest KMS wait) → elasticache → aurora (independent; order for downtime).
  3. mysql-sg 13306 + Aurora reboot 13306 inside pods=0 (no live 3306 client).
  4. Secret resync from bastion (Redis endpoint+SSL; aurora :13306 JDBC) BEFORE restore.
  5. ONE restore from /tmp/replicas.txt (abort-if-zero guard). Unfreeze CI/CD.
